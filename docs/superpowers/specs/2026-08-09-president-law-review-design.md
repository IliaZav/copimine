# Президент: рассмотрение законов и livebar

## Цель

Дать администратору единый рабочий процесс для законов действующего президента:

- увидеть ожидающие законы в игровом меню `Выборы -> Президент`;
- открыть полный текст закона в книге;
- одобрить или отклонить закон с сохранением существующих ограничений workflow;
- после одобрения показывать закон в игровом livebar, на сайте и в игровом GUI;
- в админке сайта выполнить те же действия через защищённый endpoint и книжное окно;
- при активном президентском сроке не переключать livebar на кандидатов и графики;
- не запускать устаревшее объявление при использовании мандата по блоку.

## Границы

Изменяются только CopiMineElectionCore, AdminPlus mandate guard и election admin web.
Схема базы данных, выборы/голосование, варка и AR не меняются.

## Игровой GUI

Текущий `openRpPresidentMenu` получает pending laws активного срока вместе с данными
президента. Для каждого закона показывается карточка. Клик открывает detail-menu с
кнопкой `WRITTEN_BOOK`; книга содержит полный текст закона. Кнопки approve/reject
вызывают существующий `reviewLaw`, поэтому сохраняются проверки активного срока,
лимита пяти опубликованных законов, cooldown замены и принадлежности закона сроку.
После успешного решения меню обновляется через тот же async snapshot flow.

## Сайт

`election_detail_sync` возвращает опубликованные и pending законы текущего активного
срока вместо намеренного обнуления. Добавляется admin-only endpoint
`POST /api/elections/president-laws/{law_id}/review` с теми же бизнес-ограничениями,
аудитом и подтверждением чувствительного действия. В активной панели выборов
появляется секция «Законы президента» с книжным просмотром и кнопками approve/reject.

## Livebar

При `PRESIDENT_TERM` sidebar всегда рендерит президентский блок: президент, налог и
опубликованные законы. Цикл страниц кандидатов разрешён только до президентского
срока. Snapshot уже загружает опубликованные законы активного выборного цикла, поэтому
после approve достаточно вызвать существующий refresh/push.

## Мандат

Активный ElectionCore владеет обработкой мандата. AdminPlus не должен выполнять
`presidentHourlyAnnouncement` ни для одного right-click мандата; это устраняет старый
побочный эффект, который оставлял экранный текст при клике по блоку.

## Проверки

Добавляются RED-контракты для:

1. pending-law query и доступности закона в текущем President GUI;
2. книжного просмотра и approve/reject action routing;
3. backend route, transaction/review constraints и frontend book/review controls;
4. запрета candidate-page livebar во время `PRESIDENT_TERM`;
5. отсутствия legacy mandate announcement path.

После реализации выполняются контрактные тесты, сборка плагинов, bytecode/JAR
проверка, SHA-256 локальных и серверных JAR, Paper-remapped проверка и статус
`copimine-minecraft`.
