# End Rift Event — актуальная спецификация

Статус: единственная актуальная игровая спецификация для текущей реализации.
Серверная логика authoritative: мир, сущности, урон, цели, generation события,
награды и очистка решаются плагином. Клиентский мод отвечает только за модель,
анимацию и визуальные эффекты, а при отсутствии ассета игровой процесс не
останавливается.

## Границы

Событие работает только в окружении `local` или `staging`. Текущий конфиг —
schema 4, мир арены — `CopiMine`, максимум — 20 участников. Состояние события,
журнал депозита и журнал временных изменений блоков сохраняются до изменения
мира. Боевые данные и внешний сервер не входят в локальный запуск.

У события один generation. Любая сущность, задача, снаряд, отображение и запись
в журнале обязаны иметь event id и generation. При несовпадении generation объект
не может наносить урон, выбирать цель или менять блок.

## Канонический граф

`UNCONFIGURED -> COLLECTING -> READY_FOR_PLAYERS -> START_RITUAL -> WAVE_1`

Далее каждая волна завершается через свою паузу:

`WAVE_1 -> INTERMISSION_1 -> WAVE_2 -> INTERMISSION_2 -> WAVE_3 ->`
`INTERMISSION_3 -> WAVE_4 -> CORE_RESTORATION -> WAVE_5 -> INTERMISSION_5 ->`
`WAVE_6 -> INTERMISSION_6 -> WAVE_7 -> PRE_BOSS_COOLDOWN -> BOSS_CINEMATIC ->`
`BOSS_ACTIVE -> BOSS_FINISH -> VICTORY_PROCESSING -> UNLOCKED`.

Канонические цели волн по порядку: `RIFT_CARRIERS`, `RIFT_HUNT`, `RIFT_GATES`,
`OBELISK_ASSAULT`, `BLACK_FOG`, `COLLAPSE_RINGS`, `REALITY_SPLIT`.

Каждый переход проверяет текущий event id, generation, мир, Core и владельца
ресурсов. Состояние `RECOVERY_REQUIRED` используется при неполной записи или
неразрешённом журнале.

## Подготовка и руны

Администратор ставит Core командой `/cmend core set <игрок>`, наведя прицел на
реальный блок. Плагин сохраняет именно выбранную клетку, не позицию игрока.
`/cmend core info` показывает состояние, координаты и generation.

`/cmend resources add <MATERIAL> <amount>` добавляет ресурсы, а
`/cmend resources status` показывает прогресс. После заполнения появляются
пять рун на полу вокруг Core. Одна руна может быть занята только одним игроком,
один игрок — только одной руной. На каждом тике проверяются мир, высота,
радиус, spectator/dead/offline и уникальность. Свободная руна остаётся видимой;
занятая меняет цвет и подаёт локальный визуальный сигнал.

Когда все требуемые участники заняли разные руны, начинается `START_RITUAL`.
Непрерывное удержание длится 5 секунд, а защитный тайм-аут — 60 секунд.
Команда `/cmend ritual cancel confirm` отменяет ритуал без запуска волны.

## Волны

### Wave 1 — Rift Carriers

Постепенно появляются носители разлома. У каждого event-owned моба есть
ограниченный жизненный цикл: spawn, objective, death/cleanup. Визуальная волна
идёт от Core кольцами, опасные места заранее телеграфируются, награда после
победы выдаётся на Core один раз.

### Wave 2 — Rift Hunt

Мобы выбирают только живых участников события и используют контекст охоты,
позицию цели и недавнюю историю выбора. Цель не меняется каждый тик; смена
происходит bounded-ротацией, чтобы поведение оставалось читаемым.

### Wave 3 — Rift Gates

На арене ровно три event-owned прохода. Каждый проход состоит из временных
блоков и визуального портала, имеет журнал оригинальных блоков и открывается
слоями. В каждой группе есть два push-моба. Блоки арены не ломаются, а после
завершения возвращаются из журнала. Для ручной проверки доступны
`/cmend gate preview`, `/cmend gate open [ticks-per-layer]`,
`/cmend gate close [ticks-per-layer]`.

### Wave 4 — Obelisk Assault

Появляются event-owned обелиски на безопасных клетках вокруг Core. Количество
ограничено профилем давления; в текущем конфиге максимум шесть. Обелиск имеет
3 integrity HP, меняет состояние `FULL -> DAMAGED -> CRITICAL -> DESTROYED` и
снимает HP только от отражённого event Rift Fireball. Меч, стрела, взрыв, огонь,
обычный снаряд и урон моба ничего не меняют.

Обелиски собираются снизу вверх после телеграфа, пульсируют кольцом радиусом
5 блоков и стреляют с интервалом 80 тиков. Общий лимит event fireball — 8;
выстрелы staggered. Снаряд имеет event id, generation, тип и состояние
`OUTBOUND/REFLECTED`; после удара игрока направление меняется по направлению
отражения. При попадании в любой текущий обелиск отражённый снаряд снимает один
HP. Взрыв не меняет блоки, не оставляет огонь и не наносит урон боссу.

Попавший игрок получает 6 урона, Blindness I на 40 тиков, Weakness I,
Nausea II и Slowness I на 60 тиков. Пульсация наносит только последние три
эффекта на 60 тиков и не наносит прямой урон. Эти короткие длительности не
умножаются общим масштабированием. После третьего отражения обелиск имеет
короткое схлопывание и полностью удаляется вместе с временными клетками.

### Core Restoration

После Wave 4 Core восстанавливает энергию, возвращает зарегистрированные
временные блоки и выдаёт волновую награду ровно один раз. Сбой на этом шаге
оставляет `RECOVERY_REQUIRED`, а не создаёт второй комплект награды.

### Wave 5 — Black Fog

Проходит три ограниченных цикла тумана. Перед сменой опасного состояния игроки
видят безопасную зону и получают bounded freeze/telegraph, затем поле постепенно
возвращается. Сценарий не создаёт бесконечных задач и не превышает общий budget.

### Wave 6 — Collapse Rings

Команды игроков объединяются в пары. Для каждой пары сохраняются участники,
локальный таймер и относительный угол вращения. Таймер начинается при первом
выбывшем, дедлайн трактуется включительно; при успехе пара закрывается, при
тайм-ауте возвращается в состояние двух живых. Данные одной пары не видны и не
влияют на другую.

### Wave 7 — Reality Split

Перед началом создаются изолированные комнаты и явные проходы. До открытия
прохода target selection, pathfinding, projectile, AoE и teleport разрешены
только внутри назначенной комнаты. Назначение хранится по generation и UUID.
После выполнения всех комнат границы объединяются контролируемым переходом.

## Давление и ИИ

`PressureBudgetController` держит hard cap 56 живых event-owned мобов. Резервы
не считаются активным давлением, а новые группы появляются постепенно. Профили
2, 3, 5, 10, 15 и 20 игроков меняют здоровье специальных целей, число угроз,
частоту способностей и target pressure; число мобов не растёт бесконечно.

ИИ использует objective/role/context, а не необозначенный номер волны. Обычные
скелеты стреляют по игрокам события, усиленные скелеты используют ограниченные
стрелковые механики, эндермены применяют bounded teleport только внутри арены.
Командир волны даёт ближайшим event-owned мобам небольшой бонус до своей смерти.
Натуральные мобы и игроки вне roster не становятся целями.

## Босс

Босс — одна настоящая Bukkit/Paper `LivingEntity` с реальным max health. Базовое
значение для двух игроков — 5000; scaling `BossHealthPolicy` поднимает его до
20000 для 20 игроков. Virtual HP и скрытая вторая шкала в текущем flow отсутствуют.
Каждый входящий hit применяется к текущему entity health с его final damage;
серия одновременных hit не перезаписывает результат последним ударом.

Пороговые фазы: `AWAKENING` (100–80%), `HUNT` (80–60%), `RIFT` (60–45%),
`OVERLOAD` (45–30%), `RAGE` (30–20%), `LAST_SEAL` (20–0%). Урон разрешается
обычной политикой причин. Cast state управляет telegraph/execution/recovery и
не является общей неуязвимостью.

В `LAST_SEAL` появляются постоянные event tentacles с серверным hitbox и
клиентской моделью. Их visual socket не определяет попадание. Используются
состояния `IDLE`, `EMERGE`, `TELEGRAPH_GRAB`, `GRAB_SUCCESS`, `HOLD`, `THROW`,
`GRAB_MISS`, `HURT`, `DEATH`, `RETRACT`, `SPAWN_UNDER_PLAYER` и
`SHIELD_CHANNEL`. Маркеры `CONTACT`, `HOLD_LOCK`, `THROW_RELEASE`,
`RECOVERY_START`, `HIDE_BELOW_FLOOR` синхронизируют видимую анимацию с серверным
решением.

## Клиент и VFX

Клиент получает семантические события boss bar, phase, animation, tentacle
progress, beam/ribbon и tombstone. Неизвестная animation id остаётся
`UNKNOWN` и логируется; она не превращается молча в `IDLE`. World-space beams и
ribbons рисуются непрерывным bounded renderer, а не длинной линией из тысяч
частиц. Обычный ванильный fireball не получает event texture: Rift Fireball
имеет отдельный event visual id и безопасный fallback.

Asset pipeline проверяет PNG/JSON/atlas/audio до упаковки. Ванильные текстуры
не изменяются. Все временные displays и overlays имеют event owner и исчезают
при tombstone, reset или generation boundary.

## Награды

Результаты сохраняются до физической выдачи. Каждый официальный победитель один
раз получает `rift_core_shard`; для каждого игрока отдельно сохраняется
независимый roll `night_cloak` с шансом 30%. Артефакты создаются только через
Artifacts API с authenticity и owner binding. Повторный запуск после рестарта
читает сохранённый результат и не делает повторный roll.

## Очистка и восстановление

`/cmend cleanup confirm`, reset, удаление Core, смерть босса, смена generation,
disable плагина и recovery удаляют задачи, мобы, босса, обелиски, fireball,
display, portals, tentacles, VFX и временные блоки. Блоки восстанавливаются
только через HazardMutationJournal; незакрытая запись блокирует продолжение до
restore. Для аварийного завершения предусмотрены отдельные cleanup и reset
команды, а не прямое удаление файлов состояния.

## Проверка

Минимальные unit/contract проверки: граф, schema 4, rune bijection, pressure
cap, реальные hit series, phase boundaries, obelisk scaling/integrity,
reflection-only damage, boss immunity только для Rift Fireball, chamber
isolation, rewards idempotency, asset catalog и current sound catalog. Runtime
проверка должна отдельно покрывать 2, 3, 10 и 20 игроков, Paper restart/recovery,
полное прохождение и визуальные сцены. Непроведённая runtime или visual
проверка в отчёте обозначается `NOT VERIFIED`.
