# Почта, SMS и вход через VK ID

## Что уже реализовано

Сайт подтверждает почту и телефон одноразовым кодом, позволяет входить по подтверждённому контакту и восстанавливать пароль. VK ID работает через серверный обмен кода авторизации; существующий аккаунт привязывается из настроек после подтверждения владельца.

Письма и SMS обрабатывает отдельная сохраняемая очередь. Перезапуск API не теряет запросы. Рабочий режим использует SMTP с TLS и API SMS.RU; автономный HTML не отправляет сообщения. Реквизиты провайдеров не включены в архив и не передаются JavaScript.

## 1. Указать реквизиты без правки кода

Из папки сайта запусти на своём сервере:

```sh
python scripts/configure_auth.py --config /etc/copimine-site/site.json --origin https://copimine.ru
```

Мастер сохранит остальные настройки существующего JSON, запросит выбранные сервисы и запишет закрытый файл атомарно. Пароли SMTP и ключ SMS вводятся без отображения. Режим отправки выбирается отдельно: Enter сохраняет текущий disabled/live, изменение только VK не включает отправку. На Windows используй путь к закрытому каталогу вне папки сайта и ограничь доступ к нему своей учётной записью и пользователем службы.

Для ручной настройки поля находятся в `deploy/site.example.json`. Они читаются только из закрытого файла `--config` или серверных переменных окружения. Явное значение JSON имеет приоритет над окружением, включая пустую строку. Для использования значения из окружения удали соответствующий ключ из JSON. Мастер не регистрирует аккаунты у провайдеров, не меняет DNS и не проверяет доставку отправкой.

## 2. Почта

Нужны SMTP-сервер, порт, логин, пароль и разрешённый адрес отправителя твоего почтового сервиса:

| Параметр | Значение |
|---|---|
| CM_NOTIFY_MODE | live для отправки, disabled для отключения |
| CM_SMTP_HOST | SMTP-хост из настроек провайдера |
| CM_SMTP_PORT | Порт провайдера; обычно 587 для STARTTLS или 465 для TLS |
| CM_SMTP_TLS | starttls или tls |
| CM_SMTP_USER | SMTP-логин |
| CM_SMTP_PASSWORD | SMTP-пароль или пароль приложения |
| CM_SMTP_FROM | Подтверждённый адрес отправителя, без отображаемого имени |
| CM_NOTIFY_EMAIL_DAILY_LIMIT | Общий предел сообщений за последние 24 часа; по умолчанию 1000 |

Пароль передаётся SMTP только после установки TLS. Проверка сертификата включена. Нешифрованного режима нет.

В кабинете почтового сервиса подтверди домен и добавь выданные им DNS-записи SPF и DKIM; политику DMARC настрой для своего домена. Не копируй случайные значения SPF/DKIM из примеров: они зависят от выбранного отправителя. Эта сборка подключается к SMTP; собственный почтовый хост с входящей почтой, DNS и репутацией IP отдельно не разворачивает.

После настройки зайди в **Настройки → Способы входа**, запроси подтверждение своей почты и введи пришедший код. Доставка считается проверенной после реального получения письма и успешного ввода кода. Ответ SMTP «принято» сам по себе не подтверждает попадание во входящие.

После подтверждения почты на неё также поступают уведомления об оформлении заказа, подтверждённом пополнении, ответе поддержки и смене пароля. Каждое такое уведомление связано с зафиксированной операцией; содержимое обращения в письмо не включается.

## 3. SMS

Используется [API SMS.RU](https://sms.ru/docs/api/api_group_sms/send):

| Параметр | Значение |
|---|---|
| CM_SMSRU_API_ID | API-ключ из кабинета SMS.RU |
| CM_SMSRU_SENDER | Согласованное имя отправителя; необязательно |
| CM_NOTIFY_SMS_DAILY_LIMIT | Общий предел сообщений за последние 24 часа; по умолчанию 100 |

Для отправки нужны активный кабинет провайдера и его доступные лимиты. Номер принимается в международном формате, например +7…, с нормализацией пробелов и скобок. Сервис проверяет результат для конкретного получателя и сохраняет идентификатор отправки.

По SMS отправляются коды входа, восстановления и подтверждения номера. Рекламных рассылок нет. Ограничения по IP, контакту и общему суточному бюджету уменьшают риск злоупотребления платной отправкой.

## 4. VK ID

Зарегистрируй приложение сайта в кабинете VK ID и укажи **ID приложения** в `vkClientId` либо `CM_V6_VK_CLIENT_ID`. Для origin https://copimine.ru разрешённый callback должен быть строго:

```text
https://copimine.ru/api/v6/auth/vk/callback
```

При другом домене замени origin при запуске API и callback в кабинете VK ID одним и тем же адресом. Production callback использует HTTPS. Возвращаемая страница сайта фиксирована: `/#auth/vk`.

Используется VK ID Authorization Code с PKCE S256, state, device_id и привязкой к текущему браузеру. Данные пользователя подтверждаются серверным user_info. Код и токены провайдера не сохраняются в браузере, базе аккаунтов или журнале.

Протокол сверён с официальным [VKCOM/vkid-web-sdk](https://github.com/VKCOM/vkid-web-sdk/blob/8ff76cfe59ea72e370c4c6c3b40712ecfd43aadd/src/auth/auth.ts). Адрес авторизации — https://id.vk.ru. Сторонний SDK в страницу не загружается.

- У существующего пользователя: **Настройки → Способы входа → Подключить VK**.
- У нового пользователя: **Войти через VK**, затем отдельный ник сайта, почта и пароль CopiMine.
- Совпадение имени или почты VK с существующим аккаунтом не привязывает его автоматически.
- Служебная роль всегда требует код приложения 2FA после VK.
- Отключение VK отзывает остальные сеансы этого аккаунта. Текущий сеанс после подтверждения владельца остаётся доступным.

Сохранён только постоянный ID VK, привязанный к аккаунту, отображаемое имя и дата привязки. Email и телефон из ответа VK не принимаются как подтверждённые контакты CopiMine.

## 5. Запустить обработку очереди

API и обработчик должны использовать один origin, один закрытый JSON и один каталог данных:

```sh
python server.py --data-dir /var/lib/copimine-site --config /etc/copimine-site/site.json --origin https://copimine.ru notification-worker
```

Образец постоянной службы — `deploy/copimine-notification-worker.service.example`. После изменения реквизитов перезапусти API и эту службу.

Проверить наличие настроек и состояния очереди без вывода секретов:

```sh
python server.py --data-dir /var/lib/copimine-site --config /etc/copimine-site/site.json --origin https://copimine.ru check-integrations
```

Команда показывает конфигурацию, а не результат внешней проверки учётных данных. `GET /api/v6/auth/providers` сообщает браузеру только доступные способы входа; пустой ключ не создаёт работающую кнопку.

## 6. Коды, сеансы и восстановление

Код содержит 6 цифр, действует 10 минут и используется один раз. Доступны 5 попыток ввода, повторный запрос — не раньше 60 секунд. Ограничение запросов относится также к неизвестному контакту; публичный ответ не раскрывает, существует ли аккаунт.

Вход и восстановление работают только для ранее подтверждённых контактов. Подтверждение привязки выполняется в текущем аккаунте. Поле почты в профиле само по себе не подтверждает адрес; его изменение отзывает прежнюю верификацию и ожидающие коды.

После восстановления новый пароль заменяет старый, все прежние сеансы отзываются одной транзакцией. Обязательный TOTP администрации и включённый пользователем TOTP сохраняются. SMS, письмо или VK не снимают второй фактор.

Код и получатель в ожидающей отправке зашифрованы. Проверка кода использует HMAC. Файл `notification.key` создаётся в закрытом каталоге данных с ограниченными правами; альтернативный ключ можно передать через `notificationKey` или `CM_V6_NOTIFICATION_KEY`.

Сохраняй резервную копию этого ключа вместе с защищённой резервной копией базы. Потерянный или заменённый ключ не генерируется молча поверх существующих контактов: запуск завершается с ошибкой. Не публикуй файл ключа и не меняй его вручную.

## 7. Неопределённый результат отправки

Состояния очереди: queued → sending → accepted, uncertain либо cancelled. Если соединение оборвалось после возможного принятия сообщения провайдером, обработчик не отправляет тот же код бесконечно. Неполученный код можно запросить заново после интервала; предыдущий код этого браузера перестаёт действовать.

Содержимое отправленного задания удаляется из очереди. Журнал сохраняет технический результат без кода, адреса получателя и паролей провайдеров. Коды с истёкшим сроком, отозванным сеансом или изменившейся учётной записью не отправляются.

## Проверки в этой сборке

Автоматические тесты проверяют SMTP/TLS- и SMS.RU-адаптеры на подставленных транспортах, шифрование очереди, одноразовость, параллельные запросы, истечение, попытки, привязку браузера, смену контакта и обязательный TOTP. VK проверяется с подставленным ответом официального протокола. Интерфейс проходит сценарии успеха, ошибок и недоступного провайдера.

Реальные SMTP/SMS-сообщения и вход пользователя в зарегистрированное приложение VK при сборке не выполнялись: действующие реквизиты этих сервисов не входят в исходники.
