# CopiMine AR artifacts: server hotfix and local Variant A

## Scope

This change is split into two ordered stages:

1. A production hotfix for the already deployed release: restore the AR
   pickaxe's normal Efficiency enchantment at the maximum supported vanilla
   level, restore the teleport compass cooldown to the pre-`de5a036` value of
   15 seconds, and repair the generated vanilla crossbow and torch base models.
   The world, plugin databases, elections, brewing, shops, ATM, and website are
   outside this stage.
2. A local-only implementation of Variant A from the attached specification:
   `gravedigger_contract`, `berserker_heart`, and `signal_bell`. The local
   runtime uses isolated state and is not uploaded to production in this task.

## Existing seams

- `CopiMineArtifacts` remains the only production plugin implementation.
- Catalog entries continue to come from `copimine-artifacts/items.yml` and the
  existing AR/Donation shop and delivery flow.
- Item identity continues to use `artifact_item_id` and
  `artifact_unique_item_id`; no new Minecraft item ID or client mod is added.
- Bukkit inventory, ItemStack, TileState, PDC, GUI, damage, death, and teleport
  work stays on the main thread. Database work stays on the existing executor.
- Resource-pack models continue to be generated by
  `resourcepacks/build-resourcepack.py`.

## Stage 1: production hotfix

### Pickaxe

The AR pickaxes keep their existing catalog identities and mining abilities.
The `smena_bez_perekura_pickaxe` item no longer grants a Haste potion effect
when activated. Pickaxe metadata is normalized to `Enchantment.EFFICIENCY` at
level 5 (the maximum vanilla level), including already issued instances after
join/reload. Other pickaxes retain the shared Efficiency normalization without
the Haste replacement.

### Compass

The donation teleport compass keeps its negative-visual-effect removal and is
configured at the historical 15-second cooldown in both the catalog and runtime
constant. This value is player-scoped through the existing cooldown path.

### Vanilla models

The generated base model for `crossbow` uses vanilla `crossbow_standby` as its
layer texture while retaining all vanilla pulling/charged predicates. The
generated base model for `torch` inherits `minecraft:block/torch`, retaining the
vanilla 3D model. Custom-model-data overrides remain after vanilla predicates.

## Stage 2: local Variant A

### Gravedigger contract

- PAPER item, AR shop, 300 AR, EPIC, max stack 1, authenticated physical item
  only in hotbar/main inventory/offhand.
- On one eligible death, consume exactly one matching physical instance and
  write an owner-bound pending record to the player's PDC with a nonce and
  death location. `keepInventory` is never changed.
- `/cmartifacts grave` is player-only and owner/nonce checked. It validates a
  loaded, safe destination near the death point, teleports first, then consumes
  the matching pending record. Any failed or cancelled attempt leaves it
  pending. The pending record survives relog/restart.

### Berserker heart

- NETHER_STAR, Donation shop, 200 donation, owner-bound, persistent, max stack
  1, nonrepairable, 420-second player-level cooldown.
- The damage handler triggers only for nonlethal damage leaving real health
  below 10% of max health; exactly 10%, 11%, lethal damage, and foreign/fake
  items do not trigger it.
- Cooldown is written before effects are applied. Strength II, Speed II, and
  Regeneration II last 10 seconds and do not replace stronger active effects.
  The heart is not consumed. A 1 Hz fallback only covers damage paths that do
  not expose the normal event, without scanning worlds or inventories.

### Signal bell

- BELL, AR shop, 150 AR, EPIC, max stack 1, one active binding per physical
  unique bell instance. It is movable and storable; placement of the official
  bell item remains cancelled so vanilla bells are unaffected.
- Right-click opens the existing session-bound GUI. Binding requires a current
  chest/trapped-chest target within the bounded raytrace and revalidates the
  player, exact bell identity, candidate, and protection state before writing a
  new nonce to the bell and both sides of a double chest.
- On a successful, non-cancelled chest open, the marked chest receives an
  append-only bounded open history containing opener UUID/name and the actual
  timestamp. Notification scans only online PlayerInventories at that event;
  the bell owner does not need to be online. When the owner later opens the
  bell GUI, the stored history is displayed, so offline periods are preserved.
  Old bindings are invalidated by nonce mismatch and old chunks are never
  force-loaded.
- Runtime debounce is keyed by bell instance, opener UUID, and binding nonce.

## Verification and release boundary

The server hotfix must pass focused regression tests, resource-pack build and
inspection, plugin compilation, and a remote hash/status check before upload.
The remote world and databases are not modified.

The local Variant A must pass pure policy tests, artifact/catalog contract
tests, plugin build, resource-pack build/inspection, and isolated local runtime
smoke tests. Any unavailable Paper/runtime verification is reported as
unverified rather than inferred as passing. No local Variant A files are
uploaded to production in this task.
