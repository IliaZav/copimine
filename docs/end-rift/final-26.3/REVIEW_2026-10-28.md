# Проверка изменений End Rift, 28 октября 2026

Проверен набор изменений после `6bde934f` до `563a2c5f` и текущая реализация затронутых обработчиков. Объём приёмки: код, сборки, автоматические тесты и GitHub CI. Игровое прохождение, F2 и развёртывание новой версии не выполнены; `nativeVerified=false`.

## Подтверждённые ошибки и исправления

- Бросок Кагуне напрямую списывал HP и применял импульс, обходя отмену урона. Теперь удар проходит через живой хитбокс Кагуне: действуют обычная обработка урона, броня и protection-плагины; отклонённый удар не вызывает ложный hurt/импульс. Производственный обработчик проверен исполняемой регрессией.
- При смертельном ударе переход в LAST_SEAL обрезал урон даже без живых защитников или при отключённой механике. Щит учитывается только после фактического успешного создания защитников. Явный переход в recovery по-прежнему останавливает выдачу победы.
- Малый серверный carrier на следующем тике возвращался к полному масштабу. Spawn и tick теперь сохраняют размер и центрирование из настройки малой роли. Это проверка серверного преобразования, не визуальная приёмка Minecraft.
- Жерло Inferno имело контакт на 16-м тике, но вызывалось раз в 20 тиков по глобальному времени боя. Отдельный ticker обновляет жерла каждый тик от начала каста; урон пола остаётся раз в 20 тиков. Перед первым извержением действительно проходят 16 тиков предупреждения. Звук предупреждения не повторяется каждый тик; отменённый урон не подбрасывает игрока. Неучастники не получают урон жерл или пола.
- Отрицательный тест выбора JDK предполагал, что `java` из PATH обязательно является Java 21. При закреплённой Java 25 в PATH тест ошибочно отклонял корректный resolver. Теперь версия отрицательного JDK проверяется до его использования.
- В lock-файле отсутствовали некоторые опубликованные кандидаты EndEvent. Их SHA-256 восстановлены из истории Git и сохранены в обоих списках разрешённых предшественников.

## Автоматические результаты

- Регрессии сначала воспроизводили обход защиты броском, невидимый щит, сброс масштаба, недостижимый контакт жерл и урон постороннему зрителю; после исправления проходят.
- Затронутый набор Python-проверок: **348 passed**, 79 предупреждений Pillow об устаревшем API.
- Полный локальный прогон до исправления отрицательной JDK-фикстуры: **2417 passed, 7 failed, 7 skipped**. Одна ошибка исправлена; повторный набор toolchain-проверок: **4 passed**. Остальные шесть ошибок — `PermissionError` при чтении существующих защищённых runtime JAR/receipt; их ACL и строгие проверки не изменялись.
- Изолированный снимок конечного production source собран дважды закреплёнными Gradle 9.8.1 и JDK 25.0.4.1; JAR совпал. Размер **1965691** байт, SHA-256 **`ae8cc781ae09287e50ec366fdb5860a11e2b5415659b3628299d0f3dae2920e4`**.
- Проверки обработчиков и JAR/lock на этом изолированном снимке: **8 passed**. Это не проверка установленного сервера.
- Локальный клиентский JAR совпал с размером и SHA-512 текущего `profile.lock.json`.
- Полный итоговый GitHub CI следует проверять по SHA коммита, содержащего эти исправления. Зелёный предыдущий коммит не заменяет эту проверку.

## Проверка удалённого сервера

Обе существующие игровые службы активны. Новая версия плагина не устанавливалась, службы не перезапускались. Установленный тестовый EndEvent имеет SHA-256 `5342d7793aa90bd36208f60f5ed44443a54ef8a44e62064112fcc3324db8b117`; результаты новых исходников к нему не приписываются.

Права корня тестового сервера исправлены с `0777` на `2750`, а `server.properties` — с `0644` на `0640`. Владельцы и содержимое файла не изменились; совпадение содержимого проверено SHA-256. Миры, PostgreSQL, приватные env-файлы, пароли и резервные копии не изменялись. Ничего из существующих данных не удалялось. Настройка sudo на 100 часов автоматически не применялась.
