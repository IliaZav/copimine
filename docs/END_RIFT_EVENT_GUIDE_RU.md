# End Rift: инструкция для запуска и прохождения

Документ соответствует конфигурации `copimine-end-event/config.yml` и плагину `CopiMineEndEvent`. Все команды ниже относятся к `/cmend`. Команды управления доступны оператору с правом `copimine.endevent.admin`, тестовые команды — с правом `copimine.endevent.test`.

Плагин работает только в установленном сервере. В текущей локальной сборке `environment: local`; эти команды не должны выполняться на боевом сервере.

## Что сделать до начала

1. Убедиться, что загружен мир `CopiMine` и выбран обычный твёрдый блок для ядра.
2. Настроить ядро. Для настройки из игры встаньте так, чтобы прицел точно смотрел на нужный блок, и выполните:

```text
/cmend core set <количество игроков>
```

Принимается от 2 до 20 игроков. Команда берёт именно блок под прицелом в пределах 8 блоков, а не блок под ногами. Ванильный блок не заменяется: поверх него создаётся визуальный слой ядра. Руны создаются на полу вокруг ядра и также не меняют ванильный пол.

Для локальной подготовки из консоли можно указать координаты без наведения:

```text
/cmend core setat <x> <y> <z> <количество игроков>
```

`setat` разрешён только для локальной конфигурации. После создания ядра плагин сам рассчитывает руны, границы арены и состояние сбора ресурсов.

3. Проверить результат:

```text
/cmend status
/cmend core info
```

4. При необходимости задать свои границы арены. Точки выбираются по реальным блокам под прицелом:

```text
/cmend arena pos1
/cmend arena pos2
/cmend arena info
```

Если свои точки не нужны, используются границы вокруг ядра: 20 блоков по горизонтали и 3 блока вверх и вниз. Вернуть эти границы можно так:

```text
/cmend arena clear confirm
```

5. Если рядом есть проход с дверью, выбрать две точки двери по реальным блокам:

```text
/cmend gate pos1
/cmend gate pos2
/cmend gate info
```

`door` — тот же самый раздел и те же команды. `pos1` и `pos2` сохраняют блок, на который смотрит игрок; его позиция не подменяется координатой ног игрока.

Для локальной консольной подготовки двери без наведения:

```text
/cmend gate setat <x1> <y1> <z1> <x2> <y2> <z2>
```

6. Проверить дверь без изменения блоков:

```text
/cmend gate preview
```

Появляется частица-подсветка выбранного объёма. Для предпросмотра блоки не заменяются.

7. При необходимости сохранить место портальной комнаты:

```text
/cmend portalroom set
/cmend portalroom info
```

`portalroom set` запоминает текущую позицию игрока. Если её не задавать, используется позиция из конфигурации.

8. Показать границу арены частицами:

```text
/cmend arena border 10
```

Число означает секунды, максимум — 300. Без числа используется 10 секунд. Граница только показывается и не ставит блоки.

## Ресурсы и руны

Ядру нужны обычные ванильные предметы:

| Ресурс | Количество |
| --- | ---: |
| Алмаз | 100 |
| Око Эндера | 64 |
| Осколок аметиста | 128 |
| Огненный стержень | 64 |

Игрок берёт предмет в основную руку и нажимает правой кнопкой по блоку ядра. В зачёт идут только эти четыре материала. Защищённые custom-предметы не принимаются. После внесения предмет удаляется только в пределах принятого количества, а прогресс сохраняется до подтверждения записи.

Проверка прогресса:

```text
/cmend resources status
```

Операторская добавка только в локальное состояние события:

```text
/cmend resources add DIAMOND 100
/cmend resources add ENDER_EYE 64
/cmend resources add AMETHYST_SHARD 128
/cmend resources add BLAZE_ROD 64
```

Сбросить прогресс можно только вне боя:

```text
/cmend resources reset confirm
```

Когда все ресурсы внесены, ядро становится заряженным. На каждой руне показывается отдельный визуальный слой. Если игрок стоит на руне, её модель меняет состояние; это не изменение ванильного блока. Если визуальный слой нужно пересобрать без сброса ресурсов:

```text
/cmend core rebuild
```

Ритуал запускается автоматически, когда на всех рунах стоят нужные игроки. Для ручной проверки готового состояния:

```text
/cmend ritual start
```

Команда сработает только в `READY_FOR_PLAYERS`. Требуется от 2 до 20 игроков, а отсчёт длится 60 секунд. Если кто-то сойдёт с руны во время ожидания, ритуал отменяется и возвращается к проверке игроков.

## Все команды управления

### Состояние

```text
/cmend status
/cmend recovery
```

Показывают фазу, координаты ядра, границы, дверь, ресурсы, руны, количество участников, мобов, босса, состояние открытия Энда и шаг победы. `recovery` выводит тот же статус.

### Ядро

```text
/cmend core set <N>
/cmend core setat <x> <y> <z> <N>
/cmend core info
/cmend core rebuild
/cmend core remove confirm
```

`set` создаёт ядро на блоке под прицелом. `setat` задаёт тот же блок координатами и работает только из локальной консоли. `info` показывает статус. `rebuild` пересоздаёт визуальные слои ядра и рун. `remove confirm` завершает текущую сессию, удаляет её руны, временные визуалы, волновых мобов и босса, а исходный блок ядра возвращает по сохранённым данным. Команду удаления нужно подтверждать отдельно.

При попытке сломать ядро в игре оператор получает окно подтверждения. Надпись этого окна является текстом интерфейса. Старый плавающий текст `Подтверждение снятия Core` не создаётся: уже загруженные старые `TextDisplay` и `ArmorStand` удаляются, а такие объекты блокируются при spawn и при загрузке чанка.

### Арена

```text
/cmend arena pos1
/cmend arena pos2
/cmend arena info
/cmend arena clear confirm
/cmend arena border [секунды]
```

`pos1` и `pos2` берут реальные блоки под прицелом. `info` показывает сохранённые точки и текущие границы. `clear confirm` возвращает стандартную арену вокруг ядра. `border` рисует её линиями из частиц на заданное время.

### Дверь или проход

```text
/cmend gate pos1
/cmend gate pos2
/cmend gate setat <x1> <y1> <z1> <x2> <y2> <z2>
/cmend gate info
/cmend gate preview
/cmend gate open [ticks-per-layer]
/cmend gate close [ticks-per-layer]
/cmend gate restore confirm
/cmend gate delete confirm
```

Все эти команды работают и с заменой `gate` на `door`.

`preview` только подсвечивает объём. `open` перед изменением сохраняет точный `BlockData` каждого блока и убирает слои сверху вниз. `close` восстанавливает тот же snapshot снизу вверх. Значение — число тиков между слоями, допустимый диапазон 1–200, значение по умолчанию 30 тиков. Чем больше слоёв, тем дольше идёт анимация; стандартная настройка стала на 5 секунд длиннее прежней.

`restore confirm` немедленно возвращает сохранённые блоки после незавершённого предпросмотра или открытия. `delete confirm` удаляет только настройку точек двери и её snapshot, а не произвольные блоки мира. Во время победы закрытие, восстановление и удаление двери запрещены: после победы она остаётся открытой, в том числе после перезапуска.

### Портальная комната

```text
/cmend portalroom set
/cmend portalroom info
```

Сохраняют и показывают точку портальной комнаты. Сама команда не перестраивает комнату и не удаляет блоки.

### Ритуал и служебная очистка

```text
/cmend ritual start
/cmend ritual cancel confirm
/cmend ritual cleanup confirm
/cmend ritual reset confirm
/cmend ritual unlock confirm
/cmend cleanup confirm
/cmend reset confirm
/cmend unlock confirm
```

`ritual start` запускает 60-секундный отсчёт из состояния готовности. `ritual cancel confirm` отменяет отсчёт. `ritual cleanup confirm` удаляет временные сущности и эффекты. `ritual reset confirm` сбрасывает только прогресс события, если бой не идёт; мир и данные игроков не меняются. Верхнеуровневый `cleanup confirm` чистит event-owned сущности текущей сессии. `reset confirm` делает безопасный сброс прогресса. `unlock confirm` открывает Энд только после настоящей победы и завершения выдачи наград; вручную обойти эту проверку нельзя.

### Волны

```text
/cmend wave spawn <1|2|3|4|5|final>
/cmend wave clear
```

`wave spawn` создаёт локальную тестовую волну без изменения official roster и без выдачи победы. `wave clear` удаляет только event-owned волновых мобов.

### Босс

```text
/cmend boss spawn
/cmend boss spawn official confirm
/cmend boss official confirm
/cmend boss info
/cmend boss damage <число>
/cmend boss phase <normal|half|final>
/cmend boss kill cleanup
/cmend boss kill simulate-victory confirm
/cmend boss spell <тип>
/cmend boss freeze|unfreeze
```

Обычный `boss spawn` создаёт тестового босса. Official-босс создаётся только после `official confirm`. `info` показывает его HP и состояние. `damage` нужен для локальной проверки порогов. `phase` принудительно переводит тестовую проверку в обычную, половинную или финальную стадию. `kill cleanup` удаляет тестового босса. `simulate-victory confirm` разрешён только настоящему official-боссу и проходит победную цепочку. `freeze` и `unfreeze` — только локальная команда для остановки/возобновления движения disposable test-босса в multiplayer-проверке; official-босс и боевой сервер этой командой не затрагиваются.

Типы заклинаний босса:

```text
void_blast
rift_projectile
rift_arrows
void_mark
summon
summon_servants
will_distortion
arena_inferno
control_reverse
```

`control_reverse` — имя тестовой команды для `will_distortion`. Остальные имена совпадают с внутренними профилями частиц и логами.

### Обелиски Разлома

`rift_obelisks` доступно только на стадии `DISTORTION`. В `ABSORPTION_CHANNEL`, `JUDGMENT_CAST` и на остальных стадиях новый cast не запускается. Обелиски — это временные `ItemDisplay`-объекты поверх арены: ванильные блоки не заменяются. Перед активацией идёт 20-тиковый телеграф снизу вверх, затем обелиск пульсирует и выпускает снаряды.

Количество определяется числом живых игроков, которые находятся в текущей арене:

| Живых игроков | Обелисков |
| ---: | ---: |
| 2–5 | 1 |
| 6–10 | 2 |
| 11–15 | 3 |
| 16–20 | 4 |

Максимум всегда 4. Spectator, offline, игроки в другом мире или вне арены и выбывшие игроки в расчёт не входят. Расстановка идёт по безопасным точкам вокруг Core; обелиски не занимают Core, не перекрывают друг друга и не меняют важные постоянные блоки.

У каждого обелиска 3 состояния здоровья. Меч, стрела, моб, взрыв, огонь и обычное заклинание HP не снимают. Единственный рабочий способ — отбить именно текущий event-owned Rift Fireball игроком. Каждое валидное отражение снимает 1 HP; после третьего попадания обелиск схлопывается и удаляется. Отражённый снаряд может попасть в любой активный обелиск, не только в тот, который его выпустил. Старое поколение события, обычный vanilla fireball и снаряд без отражения не засчитываются.

Один обелиск выпускает снаряд раз в 80 тиков, стартовые моменты обелисков разнесены. Одновременно разрешено не более 8 Rift Fireball. Снаряд нацелен только на живых участников боя и после удара игроком меняет направление. При взрыве игрок получает 6 урона, Blindness I на 40 тиков, Weakness I на 60 тиков, Nausea II на 60 тиков и Slowness I на 60 тиков. Пассивный импульс раз в 40 тиков показывает кольцо радиусом 5 блоков и даёт Weakness I, Nausea II и Slowness I на 60 тиков без прямого урона и без Blindness.

Rift Fireball не ломает блоки, не поджигает арену и не наносит урон Core или боссу. Обычный удар игрока по боссу после этого остаётся рабочим. При смерти босса, победе, reset, удалении Core, выходе из DISTORTION, смене generation, отключении плагина и восстановлении после перезапуска удаляются все обелиски, fireball, display-объекты и задачи.

Текущие безопасные значения в `copimine-end-event/config.yml`:

```yaml
boss:
  rift-obelisks:
    enabled: true
    stages: [DISTORTION]
    cooldown-seconds: [18, 24]
    health: 3
    max-active: 4
    pulse-radius: 5.0
    pulse-interval-ticks: 40
    fire-interval-ticks: 80
    max-active-fireballs: 8
    fireball-damage: 6.0
    blindness-ticks: 40
    debuff-ticks: 60
```

### Клиентский визуальный мост

```text
/cmend client status
/cmend client bindboss [игрок]
/cmend client clear [игрок]
```

`status` показывает канал и активные привязки. `bindboss` заново отправляет клиенту модель босса и HUD. `clear` снимает клиентские визуальные эффекты для одного игрока или для всех, если имя не указано.

### Диагностика

```text
/cmend debug
/cmend debug packets
/cmend debug objectives
/cmend debug hazards
/cmend debug perf
/cmend debug ai
```

`packets` показывает привязки клиента, ping игроков, частоту plugin messages и частиц. `objectives` показывает прогресс цели текущей волны. `hazards` показывает временные блоки и журнал восстановления. `perf` показывает TPS, среднее время тика и число принадлежащих событию сущностей. `ai` показывает активность ИИ, цели, выходы за границу, нахождение на ядре и текущую фазу босса.

## Волны

Количество мобов масштабируется по числу участников: от коэффициента 0,8 для минимального состава до 2,0 для больших групп. Общий предел — 56 event-owned мобов. В таблице указаны базовые числа из конфигурации; при пяти игроках это фактический состав до специальных ограничителей волны 4.

Лут после волн 1–5 появляется физически у ядра. Запись о выдаче сохраняется до создания предметов, поэтому перезапуск не дублирует награду. Для общего редкого предмета есть 30-секундное окно владельцев события.

### Волна 1: «Пробуждение»

Состав: 7 эндерменов, 10 пауков, 5 скелетов. Сразу после появления от ядра расходится большая кольцевая волна: за 2 секунды она расширяется до 20 блоков, рисуется прозрачной текстурой на полу и дублируется частицами. Нужно уничтожить всех мобов. Через 18–22 секунды ядро предупреждает о импульсе; телеграф длится 2,5 секунды. Игроки видят безопасный сектор. В опасном секторе импульс наносит 6 урона и замедляет на 3 секунды.

Лут у ядра: 12 жемчуга Края, 12 бутылочек опыта, 24 приготовленной говядины, 12 стрел, 8 железных слитков.

### Волна 2: «Охота»

Состав: 9 эндерменов, 8 пауков, 4 скелета. При старте повторяется кольцевая волна от ядра, затем нужно уничтожить всех мобов. Каждые 12–16 секунд выбирается игрок для метки Разлома. Метка показывается частицами, даёт короткое свечение и заставляет волновых мобов держать фокус на этой цели. Полная метка длится 11 секунд; если цель вышла из арены, выбирается новая.

Лут у ядра: 18 жемчуга Края, 18 бутылочек опыта, 12 золотых слитков, 18 золотых морковок, 2 золотых яблока.

### Волна 3: «Порталы»

Состав: 12 эндерменов, 1 паук, 5 скелетов, 4 элитных эндермена, 1 элитный скелет. При старте повторяется кольцевая волна от ядра. Появляются порталы: 3 для двух игроков, 4 для 3–5 игроков, 5 для 6–10 игроков, 6 для 11 и более. Каждый портал нужно удерживать игроком внутри кольца 5 секунд. Короткий выход до 0,45 секунды не сбрасывает прогресс, более долгий выход уменьшает его.

Элитные эндермены получают по одному устойчивому заклинанию: `Рывок Разлома`, `Кандалы Пустоты`, `Импульс Эха` или `Залп Разлома`. Элитный скелет всегда использует `Залп Разлома` — три стрелы с отдельным следом частиц. Все цели заклинаний проверяются как игроки; мобы не становятся целями.

Лут у ядра: 18 жемчуга Края, 24 бутылочки опыта, 4 алмаза, 12 осколков аметиста, 3 осколка эха.

### Волна 4: «Оборона ядра»

Состав: 10 эндерменов, 8 пауков, 5 скелетов, 3 элитных эндермена, 1 элитный скелет. Для 2 игроков действует предел 16 мобов, для 3–5 — 22, для 6 и более — 28. Мобы приходят небольшими группами до 4 существ с промежутками 14, 12 и затем 10 секунд; перед каждой группой ядро даёт короткий импульс кольцевых частиц.

Нужно продержать ядро 180 секунд и затем добить оставшихся мобов. Базовое здоровье цели — 1200; за каждого игрока сверх двух добавляется 300, максимум 4200. Роли врагов: быстрый налётчик, разрушитель ядра и дальняя артиллерия. Скелеты не агрятся на других мобов и стреляют только по игрокам. Удар игрока по мобу отводит его внимание от ядра на 4 секунды.

Если ядро разрушено, волна очищается, игроки получают слепоту на 5 секунд, после чего запускается новая попытка с полным здоровьем ядра.

Лут у ядра: 24 жемчуга Края, 32 бутылочки опыта, 5 алмазов, 3 золотых яблока, 3 осколка эха. С вероятностью 35% появляется общий незеритовый лом.

### Волна 5: «Шторм Разлома»

Состав: 14 эндерменов, 10 пауков, 6 скелетов, 6 элитных эндерменов, 2 элитных скелета. В течение 30 секунд арена получает один из чередующихся рисунков опасных зон: кольца, крест, сектора, движущийся безопасный остров или линии трещин. Кольцевая волна от ядра появляется и здесь, но её цвет меняется на цвет шторма.

Красные клетки становятся магмовыми блоками, опасные клетки наносят 4 урона не чаще раза в секунду и замедляют на 3 секунды. Не менее 35% площади остаётся безопасной; паутина ограничена 12 клетками. Каждые 5 секунд шторм пытается подтянуть игроков к ядру. После окончания 30 секунд временные блоки восстанавливаются по журналу.

Лут у ядра: 36 жемчуга Края, 48 бутылочек опыта, 8 алмазов, 4 золотых яблока, 6 осколков эха, 24 осколка аметиста. С вероятностью 50% появляется общий незеритовый лом.

После уничтожения пятой волны начинается кинематографическая пауза примерно 10 секунд: частицы идут от ядра, показываются предупреждения, затем появляется финальная волна.

### Финальная волна

Состав: 10 пауков, 3 скелета, 6 элитных эндерменов, 2 элитных скелета. Эндерменов обычного типа нет. Финальная волна закрывает переход к уязвимому боссу. Элитные эндермены получают устойчивые заклинания из того же цикла, элитный скелет использует тройной `Залп Разлома`, а кольцевая волна окрашена в финальный пурпурный цвет.

Пока жив хотя бы один моб финальной волны, босс не переходит в обычное уязвимое состояние. После зачистки снимается временная неуязвимость, и открывается окно атаки босса.

## Босс и его фазы

У official-босса виртуальное здоровье масштабируется по зафиксированному составу: 2 игрока — 5000 HP, затем значение плавно растёт до 10000 HP к 8 игрокам, после чего растёт до 20000 HP к 20 игрокам. Свыше 20 игроков потолок не увеличивается. Ванильное поле здоровья ограничено 2048, поэтому в статусе показываются оба значения: логическое HP события и безопасная физическая проекция. Урон игроков считается по логическому запасу, каждый входящий hit применяется последовательно и не перезаписывает предыдущий.

Босс выбирает только живых допущенных игроков. Он не берёт целью мобов, не выходит более чем на 20 блоков от ядра, не уходит выше или ниже разрешённых 3 блоков и не должен стоять на самом блоке ядра. Перемещение, отступление и телепортация проходят одну проверку безопасной позиции.

### 80–100% HP: «Пробуждение»

BossBar фиолетовый. Босс держит кольцо вокруг ядра, меняет сторону обхода и использует `Взрыв Бездны`, `Снаряд Разлома` и `Шквал Стрел Разлома`.

### 60–80% HP: «Охотник»

BossBar синий. Босс фланкует выбранного игрока, пересекает линию атаки и иногда делает короткий обратный финт. Добавляются `Клеймо Пустоты` и `Призыв слуг Разлома`.

### 40–60% HP: «Искажение»

BossBar розовый. Босс чаще меняет направление и угол атаки. К предыдущим заклинаниям добавляется `Искажение воли`: клиент получает временный эффект обратного управления. Переключение цели использует память последних целей, чтобы не бить одного игрока бесконечно.

### 20–40% HP: «Поглощение»

BossBar жёлтый. При первом входе в эту полосу босс отступает во внешнее кольцо и 5 секунд поглощает энергию ядра. В этот момент он неуязвим, а все активные снаряды и метки очищаются. После канала уязвимость возвращается, движение ускоряется, а следующая атака получает усиление.

### 0–20% HP: «Катастрофа»

BossBar красный. Босс держит ближнюю дистанцию, но сохраняет отступ от ядра, ускоряет заклинания и использует весь доступный набор. В этой фазе доступно `Пламя Разлома`: на 5 секунд опасные клетки арены становятся магмой и подсвечиваются частицами. Настоящий огонь не распространяется. Опасная клетка наносит 6 урона и накладывает усиленную слабость; защищённые клетки и безопасная доля арены сохраняются.

### Порог 10% HP: «Суд Разлома»

При достижении 500 HP начинается одноразовый финальный ритуал. Босс временно неуязвим, вокруг игроков появляются три безопасные области, а остальные получают урон, иссушение и слабость. После трёх импульсов босс переходит в состояние истощения и снова получает урон. Финальная последовательность: высасывание 60% текущего здоровья игроков с минимумом 1 HP, визуальный канал от игроков к ядру и финальный волновой заслон. Затем босс снова становится уязвимым до нуля.

## Заклинания и визуал

Каждое заклинание имеет три шага: предупреждение, летящий след частиц и удар. Невидимые серверные снаряды используются только как носители столкновения; видимый снаряд рисуется частицами.

| Команда/заклинание | Что делает |
| --- | --- |
| `void_blast` | Взрыв вокруг цели: 12 урона, отбрасывание, слабость IV на 12 секунд. |
| `rift_projectile` | Летящий снаряд Разлома: 12 урона и замедление IV на 3 секунды. |
| `rift_arrows` | Веер из трёх стрел, по 12 урона при попадании и замедление IV на 12 секунд. |
| `void_mark` | Зона радиусом 3 блока на 10 секунд: 4 урона за тик зоны, иссушение IV и замедление IV. |
| `summon_servants` | До четырёх пауков-слуг; новые два появляются на порогах 70% и 35% HP. |
| `will_distortion` | Временный контрольный эффект на выбранном игроке, доступен после порога 50%. |
| `arena_inferno` | Магмовые опасные клетки и огненный визуал на 5 секунд, с безопасной долей арены. |

Заклинания мини-боссов:

| Заклинание | Эффект |
| --- | --- |
| `rift_step` | Рывок к безопасной точке рядом с игроком, 5 урона и замедление на 3 секунды. |
| `void_snare` | 4 урона, замедление на 3 секунды и слабость IV на 12 секунд. |
| `echo_pulse` | 5 урона по игрокам в радиусе 5 блоков, отбрасывание и слабость IV на 9 секунд. |
| `arrow_salvo` | Три летящие стрелы, по 8 урона и замедление на 3 секунды; цель только игрок. |

Уровень эффектов ограничен IV уровнем, чтобы клиент не ломал отображение зелий. Все задачи заклинаний проверяют поколение сессии, состояние босса и фазу; после смерти босса, удаления ядра, отмены или перезапуска снаряды и эффекты чистятся.

## Что происходит после победы

1. После смерти настоящего official-босса удаляются все волновые мобы, слуги, снаряды, метки, временные эффекты и BossBar.
2. Запускается durable-выдача: осколок ядра Разлома каждому участнику official roster, `return_stone` выпадает в мире, назначенному получателю выдаются 3000 опыта, 16 жемчуга Края и 16 плодов хоруса.
3. После подтверждения выдачи WorldCore открывает Энд.
4. Настроенная дверь открывается послойно сверху вниз и остаётся открытой. После `VICTORY_COMPLETE` команды `close`, `restore` и `delete` для этой двери блокируются.
5. Ядро и исходные полы рун сохраняются как ванильные блоки. Над ядром остаётся мемориальная надпись с никами игроков из official roster. Эти имена сохраняются после перезапуска.
6. Состояние становится `UNLOCKED`, `victory=VICTORY_COMPLETE`. Обычная игра не запускает музыку и эффекты события. Пока игроки собираются на рунах (`READY_FOR_PLAYERS`) и идёт 60-секундный отсчёт (`COUNTDOWN`), играет напряжённый инструментальный `copimine:end_rift/ritual_wait`; при начале первой волны он останавливается. Тестовая команда `/cmend test music ritual-wait [игрок]` является отдельной операторской проверкой.

## Тестовые команды

Тесты не должны применяться вместо обычного прохождения.

```text
/cmend test run creative
/cmend test run creative cancel
/cmend test wave <1|2|3|4|5|final>
/cmend test tower fail
/cmend test ai
/cmend test boss
/cmend test teleport <wave|boss>
/cmend test visuals mobs
/cmend test visuals boss [awakening|hunter|distortion|absorption|catastrophe]
/cmend test music <phase> [игрок]
```

`test run creative` проходит по визуальным и боевым стадиям без изменения official roster. `test tower fail` проверяет повтор волны 4 и доступна только во время настоящей волны 4. `test teleport` намеренно просит внешний телепорт и проверяет ограничитель арены. `test visuals` выводит привязанные модели мобов и босса. `test music` принимает `ritual-wait`, `waves`, `boss`, `half`, `final`, `victory`, `wave-1`–`wave-5`, `intermission-1`–`intermission-4`, `boss-cinematic`, `final-drain`, `final-ritual`, `final-wave`, `boss-finish`.

Основные локальные live-прогоны новой механики:

```text
& .\tests\RunEndRiftBossMultiPlayerDamageLive.ps1 -AdditionalBotNames @('RiftDamageC','RiftDamageD','RiftDamageE') -RequireSameTick
& .\tests\RunEndRiftObeliskLive.ps1
& .\tests\RunEndRiftOfficialTwoPlayerLive.ps1 -AdditionalBotNames @('EndRiftOfficialC','EndRiftOfficialD','EndRiftOfficialE')
```

В первом тесте сравнивается PDC `end_event_boss_virtual_health` до и после реальных атак пяти клиентов с суммой всех `final`-уронов в логе; `-RequireSameTick` дополнительно требует две атаки в одном server tick. Во втором проверяются telegraph, pulse, полёт и отражение Rift Fireball, все три состояния HP, иммунитет босса, отсутствие разрушения пола, обычный урон после hazard и cleanup. Последний прогон проходит официальный ритуал, все волны, все стадии босса, победную цепочку и итоговую очистку.

Ресурс-пак содержит отдельные модели и текстуры `end_event_rift_obelisk_full`, `end_event_rift_obelisk_damaged`, `end_event_rift_obelisk_critical` и `end_event_rift_fireball`. Это overlay-модели с CustomModelData 830010–830013; глобальная текстура vanilla Ghast Fireball не переопределяется. При отсутствии клиентского asset gameplay продолжает работать через серверный hitbox и fallback-частицы.

Полный набор локальных проверок из репозитория:

```text
python -m pytest -q
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\RunEndRiftEventChecks.ps1
```

При обычном перезапуске локалки текущий мир, `whitelist.json`, `ops.json`, локальная AuthMe-база и состояние события сохраняются. Сцену заново строить не нужно.
