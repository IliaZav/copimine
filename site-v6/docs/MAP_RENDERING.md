# Реальная карта CopiMine

В `assets/map` находятся 301 тайл и 3 обзорных изображения, построенные из переданного архива `copimine-map-20261016-222730.tar.gz`. Общий объём изображений — 9 004 046 байт. Это поверхность сохранённых чанков трёх измерений. Пустые и незавершённые области остаются прозрачными.

## Происхождение и охват

Исходный архив: 781 340 456 байт, SHA-256 `fee5838c92bc34e3821c1f618501544a6e286cca98489666896b533c7c7b9ad2`. Обработаны все 209 файлов регионов, содержащие 137 659 сохранённых чанков. Видимая поверхность есть у 99 940 чанков. Ошибок чтения и декодирования — 0. Версия данных сохранённых чанков — 3955; она записана отдельно от версии клиентского каталога предметов 26.3.

| Измерение | Регионов | Сохранённых чанков | Чанков с поверхностью | Незавершённых | Без видимой поверхности | Тайлов |
|---|---:|---:|---:|---:|---:|---:|
| Обычный мир | 173 | 118 501 | 88 136 | 30 365 | 0 | 230 |
| Нижний мир | 32 | 18 317 | 11 723 | 6 514 | 80 | 47 |
| Край | 4 | 841 | 81 | 760 | 0 | 24 |

В Крае архив содержит готовую поверхность только центрального острова. Остальные сохранённые чанки ещё не имеют поверхности для изображения. Дополнительные острова не дорисовываются.

Границы поверхности заданы в координатах блоков; `maxX` и `maxZ` **не входят** в диапазон:

| Измерение | X | Z | Размер поверхности | Обзор, пиксели |
|---|---|---|---|---|
| Обычный мир | −10048 … 4528 | −10080 … 4720 | 14576 × 14800 | 1458 × 1480 |
| Нижний мир | −1408 … 1968 | −1040 … 384 | 3376 × 1424 | 1126 × 475 |
| Край | −64 … 80 | −64 … 80 | 144 × 144 | 144 × 144 |

Имя архива содержит время `2026-10-16T22:27:30`, но не содержит часовой пояс. В `source.capturedAt` оно сохранено без выдуманного UTC-смещения; `captureTimeSource` объясняет ограничение. `generatedAt` обозначает время подготовки веб-карты. Полные сведения находятся в `data/map-manifest.json`, результаты проверки — в `sources/map-verification.json`.

## Как изображается поверхность

Обычный мир и Край используют сохранённую карту высот `WORLD_SURFACE` и первый не воздушный блок. Цвета усреднены по текстурам блоков, с простым освещением по перепаду высоты; окраска листвы и воды по биомам приблизительна.

В Нижнем мире скрыта бедроковая крыша: рендер идёт вниз от Y=120 и выбирает первый пол под последовательностью как минимум из четырёх воздушных блоков. Поэтому видны доступные пещеры, лава и постройки. Столбцы без такого открытого пространства прозрачны. Этот режим явно обозначен в манифесте.

Самый подробный уровень — `zoom=5`, один блок на пиксель. Размер каждого тайла — 512 × 512. Уровень 0 содержит 32 блока на пиксель. Координаты тайлов глобальные, в том числе отрицательные:

```text
blocksPerPixel = 2 ** (5 - zoom)
worldX = tileX * 512 * blocksPerPixel
worldZ = tileZ * 512 * blocksPerPixel
assets/map/{dimension}/{zoom}/{tileX}/{tileZ}.webp
```

`dimensions[].tiles.levels[].coordinates` содержит точный список существующих тайлов. Прямоугольный обзор следует размещать с пропорциями `overviewMetadata.width/height`; его нельзя растягивать до квадрата. Для привязки координат используются отдельные `bounds.width` и `bounds.height`.

## Повторный рендер архива

Нужны Python 3.11+ и Pillow. Проверенная среда использует Python 3.13 и Pillow 12.3.0. NumPy не требуется. Код обрабатывает один регион за раз в отдельном рабочем процессе; память освобождается при регулярном перезапуске процесса.

```bash
python -m pip install -r requirements-map.txt
python scripts/render_world_tiles.py /private/copimine-map-20261016-222730.tar.gz --output /private/map-staging/revision-001 --palette scripts/map-palette.json
python scripts/verify_map_assets.py --root /private/map-staging/revision-001
```

Пример для Windows, где пути с пробелами заключены в кавычки:

```bat
py -3.13 scripts\render_world_tiles.py "C:\Minecraft\snapshots\world.tar.gz" --output "C:\Minecraft\private-map-staging\revision-001" --palette scripts\map-palette.json
```

Поддерживаются архивы с отдельными папками `CopiMine`, `CopiMine_nether`, `CopiMine_the_end` или `world`, `world_nether`, `world_the_end`. Также распознаются `DIM-1` и `DIM1` внутри общей папки мира. Для другого имени передайте `--world-name NAME`. Если известны время и часовой пояс реального снимка, укажите `--captured-at 2026-10-16T22:27:30+07:00`, заменив пример фактическим значением.

## Обновление из действующего мира

Вместо архива можно передать папку мира либо корневую папку сервера:

```bash
python scripts/render_world_tiles.py /srv/minecraft --output /private/map-staging/revision-002 --palette scripts/map-palette.json
```

Для корня сервера рендер читает только значение `level-name` из `server.properties`, либо выбирает единственную папку с `region`. Если миров несколько, требуется `--world-name`. Поддерживаются вложенные `DIM-1`/`DIM1` и соседние Bukkit-папки `_nether`/`_the_end`.

Рендер читает `.mca`, необходимые внешние `.mcc` и координаты общего спавна из `level.dat`. Он не меняет файлы сервера и не блокирует запись игры. Для каждого файла сравниваются размер, время изменения, идентификатор файла и повторно прочитанный заголовок. По умолчанию допускаются три попытки стабильного чтения; `--snapshot-attempts` принимает значение от 1 до 10. Нестабильный файл или повреждённый чанк останавливает задачу с ненулевым кодом и не создаёт новый публичный манифест.

Снимок нескольких регионов не является одной атомарной операцией: сервер может записать соседние регионы в разное время. `snapshotStartedAt`, `snapshotCompletedAt`, число повторов и отпечаток фактически прочитанных файлов сохраняются в `source`. Для задержки публикации планировщик использует `snapshotCompletedAt`, чтобы возраст самых свежих прочитанных данных не оказался меньше настройки владельца. Интервал рендера, минимальный возраст снимка и отдельная задержка слоя игроков задаются в серверных настройках; в рендерере нет фиксированной задержки 12 часов.

Планировщик должен создавать новую приватную папку для каждой ревизии, дождаться успешного выхода, проверить манифест и только затем переключить опубликованную ревизию. Соседняя папка `*.render-checkpoints` содержит служебное состояние восстановления и отчёт ошибок; она не публикуется. `--checkpoint-dir` позволяет задать её явно. Флаг `--reuse-existing-tiles` предназначен исключительно для ручного восстановления тайлов, чьё происхождение уже проверено; для регулярных обновлений он не нужен.

Рендерер не создаёт слой игроков. UUID, ники, позиции игроков, инвентари, сущности, содержимое контейнеров, POI и seed не входят в тайлы или манифест. Отдельный слой игроков должен проходить самостоятельные правила авторизации, видимости и задержки на сервере.

## Проверка и выпуск

```bash
python -m unittest discover -s tests -p test_map_renderer.py -v
python scripts/verify_map_assets.py --root . --report sources/map-verification.json
python scripts/package_release.py --root . --check-only
python scripts/package_release.py --root . --output ../CopiMine_Site_v6.zip
```

Проверка тайлов полностью декодирует каждый WebP, сверяет инвентарь файлов, размеры, прозрачную маску самого подробного уровня, число чанков и границы обзора. Регрессионные тесты используют маленькие настоящие Anvil/NBT-фикстуры: отрицательные координаты, внешние чанки, три измерения, крыша Нижнего мира, нестабильный файл и повреждённый чанк.

Упаковщик запускается после окончательной сборки и проверок проекта. Он включает исходники backend и необходимые начальные каталоги `server/private/{catalog,materials,admin-actions}.json` вместе с приватными иконками. Рабочая папка `copimine-v6-state`, базы SQLite, сессии, `.env`, ключи, исходные миры, временные архивы и логи исключаются. ZIP получает список файлов с SHA-256 в `release-manifest.json`; сам ZIP проверяется перед заменой итогового файла. Параметр `--check-only` позволяет проверить состав без создания архива.
