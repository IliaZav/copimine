# Echo copies must look and fight like a real player

Date: 2026-11-18
Scope: Wave 7 player Echo presentation (client 26.3) and the AI split.
Requirement (user, verbatim intent): the echo clones must look like players -
same skin but darkened, glowing violet eyes, and every action of an ordinary
player, so the fight feels like fighting a real player; and the echo must have
its own full normal AI plus an adaptation layer that tunes itself to the specific
player's style.

Status vocabulary used below:

* **IMPLEMENTED** - the code path exists in the shipped sources.
* **AUTOMATED-TESTED** - a test proves the structure from the sources.
* **VISUAL-VERIFIED** - confirmed on a real client with real frames.
* **NOT VERIFIED** - neither of the above.

## 1. What was already there

The appearance requirement is not new work in the client; it was implemented and
only partly pinned.

### 1.1 The copy is the real vanilla player entity

`tools/minecraft-26.3/client/src/main/java/me/copimine/client/EchoPlayerView.java`
extends `RemotePlayer` (the vanilla player class) and writes the body fields from
the server's semantic frame: position, yaw/pitch and their previous values, body
yaw, head yaw, `Pose.CROUCHING`/`Pose.STANDING`, `setShiftKeyDown`, sprinting,
main arm, `tickCount`, `fallDistance`, health and bounding box. It calls
`calculateEntityAnimation(false)` for the vanilla gait curve and overrides
`isUsingItem`, `getUsedItemHand`, `getUseItem`, `getTicksUsingItem` and
`getUseItemRemainingTicks`, which is exactly what vanilla reads to draw a bow
draw, crossbow reload, shield block or eating pose. It never calls `super.tick()`,
so it is a projection and not a second simulation.

`getSkin()` returns the owner's skin; when the live skin is missing or stale the
fallback is `DefaultPlayerSkin.get(semantic.frame().owner())`, so a slow fetch
cannot show a stranger's body.

### 1.2 Vanilla animation clocks, driven by receipts

`tools/minecraft-26.3/client/src/main/java/me/copimine/client/EchoVanillaRenderer.java`
advances the vanilla bookkeeping from server receipts instead of ticking an
actor:

* gait - `player.walkAnimation.update(horizontalSpeed, 0.4F, tick - 1)`;
* swing - one six-tick `player.swing(MAIN_HAND, SwingAnimation.DEFAULT, true)`
  per accepted melee/critical serial (`SWING_TICKS = 6`);
* item use - `startUsingItem`/`stopUsingItem` once per use, so the vanilla use
  timeline owns the draw/reload/block/eat animation;
* hurt - `hurtTime = hurtDuration = 10` per accepted incoming receipt
  (`HURT_TICKS = 10`), decremented each tick;
* death - `target.deathTime = Math.max(source.deathTime, deathTicks)`, so the
  vanilla death collapse plays.

The copy is submitted by the *vanilla* renderer:
`renderer.extractRenderState(cached.player, echoState, partialTick)` followed by
`renderer.submit(echoState, matrices, collector, camera)` on an `AvatarRenderer`.
`copyCarrierAnimation` copies `ageInTicks`, `bodyRot`, `yRot`, `xRot`, `deathTime`
and `hasRedOverlay`, and the detached name tag is nulled so it never competes
with the carrier's label.

No authored replacement clips exist for the copy. That is deliberate: a second
clip set would drift the moment vanilla retimes an arm swing.

### 1.3 Darkened skin and violet eyes

`EchoVanillaRenderer.ECHO_BODY_TINT = 0xFF5A5268` (r 0x5A, g 0x52, b 0x68):
opaque, dark, and blue > red > green, i.e. a violet-biased drain rather than a
neutral grey. Vanilla has no negative brightness, so the darkening is a
translucent body pass over the already-drawn skin.

`EchoEyesFeature` submits two passes, in this order:

1. the emissive eye pass - `RenderTypes.eyes(EYES)` with full-bright light
   `0x00f000f0` and `ECHO_EYE_TINT = 0xFFB27CFF` (blue 0xFF > red 0xB2 > green
   0x7C: violet, not white);
2. the darkening body pass - `RenderTypes.entityTranslucent(state.skin.body()
   .texturePath())` tinted `ECHO_BODY_TINT`.

Both passes are skipped unless `state instanceof EndRiftRenderStateAccess bound
&& bound.copimine$isEcho()`, so ordinary players are never tinted.
`EchoPlayerRendererMixin` mixes into `AvatarRenderer` (`@Mixin(AvatarRenderer
.class)`, inject at `<init>` `RETURN`) and calls
`addLayer(new EchoEyesFeature(this))`; it is registered in
`copimineclient-26.3.mixins.json`.

The eye sheet is `resourcepacks/src/assets/copimine/textures/entity/
end_event_echo_eyes.png`: 64x64 RGBA, exactly eight visible texels of `#BB6AFF`
at the vanilla head's eye UVs (x 9, 10, 13, 14; y 12, 13), opaque on the first
row and `0x70` alpha on the second for a soft falloff. It is generated by
`resourcepacks/tools/generate_echo_eye_mask.py` and `--check` is already run by
the test suite.

**Audited and cleared (not a defect):** the client mod's own assets live under
the `copimineclient` namespace, while the eye sheet ships in the resource pack
under `copimine`. The identifier in `EchoEyesFeature` (`fromNamespaceAndPath(
"copimine", "textures/entity/end_event_echo_eyes.png")`) therefore matches the
pack, not the mod folder. The two are consistent and the pack really ships the
file; the namespace split is now pinned (see 2.2) so a future move cannot break
it silently.

## 2. What this change adds

### 2.1 The AI split already exists

The "own big normal AI plus a per-player adaptation layer" half of the
requirement is already implemented:

* `copimine-end-event/src/me/copimine/endevent/domain/wave7/
  EchoDuelCombatPolicy.java` - the full duel AI (approach/kite/strafe, melee,
  critical, ranged, shield, consumable, potion, retreat, cooldowns);
* `copimine-end-event/src/me/copimine/endevent/domain/wave7/
  EchoBehaviorStrategy.java` - the adaptation layer that turns a specific
  player's measured style into permille weights.

No new AI was written; the recent work pinned the behaviour of both (see
`ECHO_HABIT_WIRING_AND_DEAD_TEST_REVIVAL.md`).

### 2.2 New structural pins

`tests/test_end_rift_echo_eye_presentation.py` grew four tests:

* the body tint must be opaque, actually dark (every channel `<= 0x80`, green
  `< 0x60`) and keep the violet bias - a bright or neutral tint would either be
  invisible or read as a paler stranger;
* the eye texture's painted texels must be violet (blue > red > green, not
  neutral) and confined to the vanilla head's eye UVs;
* the declared eye namespace must resolve to a file the pack really ships
  (`resourcepacks/src/assets/<namespace>/<path>`), which ties the code to the
  asset instead of trusting a repo-wide filename search.

`tests/test_end_rift_echo_player_animation_contract.py` (new) pins that the copy

* extends `RemotePlayer` and never calls `super.tick()` (comment-stripped check,
  so the file's own warning about that call cannot satisfy it);
* projects crouch pose, crouch input, sprint, body yaw, head yaw, main arm and
  the gait clock;
* overrides the five use-item accessors vanilla animates from, and stops the use
  animation on death;
* wears the owner's real skin, with the owner as the fallback too;
* is driven through vanilla gait/swing/use/hurt clocks and submitted by
  `AvatarRenderer`, carrying `deathTime`;
* installs `EchoEyesFeature` on the vanilla player renderer and is registered.
