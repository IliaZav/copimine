# CopiMine 26.3: передача обновления на удалённый сервер

## Назначение

Этот документ сопровождает исправления End Rift в ветке `codex/copimine-integration-20261030`. Он описывает перенос проверенных сборок и проверку фактической установки. Удалённое развёртывание в рамках этой доработки не выполнялось.

Перед установкой закрепить точный commit SHA с успешными `static-and-contract`, `migration-postgres-contract` и `java-plugins`. Не считать старый зелёный запуск подтверждением нового SHA. Сопоставить этот документ с lock-файлами именно выбранного коммита.

Адрес SSH, учётная запись, служба и каталог удалённого сервера задаются владельцем вне репозитория. Если на машине несколько Minecraft-инстансов, сначала определить нужный; не выбирать основной мир по догадке.

## Какие артефакты устанавливать

Источник состава: `tools/minecraft-26.3/server-plugins.lock.json`. Проверенный набор содержит 30 уникальных плагинов: 20 записей `modules` и 10 разрешённых `unchangedBaseline.candidate`. Не устанавливать все исторические строки baseline. `runtimeEligible: false` исключает запись из рабочего набора.

| Кандидат | Имя в рабочем plugins | Байт | SHA-256 |
|---|---|---:|---|
| `CopiMineEndEvent-26.3.jar` | `CopiMineEndEvent.jar` | 1995773 | `c32924bcf3283606a15b233d91214edbafcc986bb593ad7b198224107686fe7d` |
| `CopiMineWorldCore-26.3.jar` | `CopiMineWorldCore.jar` | 39664 | `e6a2703e8091053f2d7e4fb53fb9b278a8d1ad62956250c64da334c780a742bc` |

Готовые собственные JAR находятся в `build/minecraft-26.3/plugins/jars/`; подготовленный набор — в `build/minecraft-26.3/server-plugins/`. Эти каталоги игнорируются Git. Один `git pull` не доставляет бинарные файлы.

Нужно перенести проверенные готовые артефакты с исходной машины либо собрать выбранный коммит поддерживаемыми инструментами. При сборке сверить итоговые байты с lock. Несовпадение нельзя исправлять подстановкой ожидаемого хеша в отчёт.

Для подготовки уже доступных кандидатов на исходной машине:

```powershell
py -3.13 scripts/minecraft/install_migration_server_plugins.py --stage-only
```

Этот режим может получать закреплённые зависимости, но не создаёт отсутствующие собственные или патченные сборки. Для таких сборок использовать соответствующие buildScript/BuildMigrationPlugins и receipts из репозитория.

Использовать `runtimeFilename` для конечного имени каждого JAR. Проверять также identity из `paper-plugin.yml` или `plugin.yml`: разные имена файлов не исключают дубли одного плагина.

## Версия платформы и специальные сборки

Проверенный профиль в `tools/minecraft-26.3/profile.lock.json`:

- Minecraft 26.3, Paper build 205, `paper-26.3-205.jar`.
- Paper: 55242379 байт; SHA-256 `a0a58f532f08054ea92eb916d3edb6ed3c86429d77175317304f6e995cce9968`.
- Java не ниже 25; закреплённая версия сборки — 25.0.4.1. На удалённой машине использовать runtime для её ОС.
- Это проверенный профиль, а не утверждение, что build 205 является последним опубликованным Paper.

Для CoreProtect применяется готовая сборка из `buildArtifact` и её `buildSha256/buildSha512/buildSize`, подтверждённая receipt. Обычные upstream-поля этой записи описывают другой артефакт. Текущая готовая сборка: 14133020 байт, SHA-256 `48b9db1a9784190c7b5c295d5ebf1433cc4c8bbbd2c3a991aa54c975dde9a7d0`.

GrimAC требуется в закреплённом варианте `creative-fix`; ProtocolLib — соответствующий закреплённый 26.3 dev JAR. Текст версии внутри plugin.yml может отличаться от имени файла: сверять согласованные identity, версию и хеши.

Если владелец просит обновить сторонние плагины сверх этого набора, проверить официальные релизы на дату установки, совместимость с выбранными Minecraft/Paper/Java и зависимостями. Более новый номер без подтверждённой совместимости не является готовой заменой. Изменённый набор требует собственных проверок и нового отчёта версий, источников и хешей.

## Обнаружение реального инстанса

До остановки определить фактические:

1. Службу systemd, контейнер или панель запуска; пользователя процесса и рабочий каталог.
2. Java executable, серверный JAR, порт и текущие версии.
3. Каталоги plugins, plugin data, миров и резервных копий.
4. Подключения production-БД и конфигурацию аутентификации, не выводя секреты.
5. Список загруженных плагинов, их зависимости и дубли.

`install_migration_server_plugins.py` и `StartMigrationTestServer.ps1` обслуживают только локальный изолированный стенд. У них нет режима установки в произвольный удалённый каталог. Их проверки loopback и локальной PostgreSQL нельзя обходить ради production-развёртывания.

`minecraft/server/start.sh` использует `purpur.jar`. Не считать его готовым запуском выбранного Paper 26.3: проверить и корректно настроить реальную службу.

Если удалённая платформа ещё несовместима с 26.3, сначала подготовить проверенную миграцию на копии данных и разрешить вопрос целевого инстанса/обновления платформы с владельцем.

## Подготовка и установка

1. Подготовить все артефакты и конкретный список замен до остановки сервера. Для каждого записать источник, commit, plugin identity, версию, конечное имя, размер, SHA-256 и SHA-512.
2. Подготовить место для резервной копии, список сохраняемых данных и порядок восстановления.
3. Штатно сохранить миры и остановить нужный Minecraft-инстанс; дождаться завершения сохранения, выхода его JVM, остановки службы и освобождения его порта.
4. Создать согласованную резервную копию миров, plugin data, конфигураций, старых JAR и БД. Проверить читаемость архива и дампа до любых замен.
5. Проверить загруженные файлы на удалённой машине до установки. Перенести только предназначенные серверные артефакты.
6. Убрать заменяемые старые JAR из активного plugins в резервный каталог. Не удалять неизвестный файл, пока не определены его identity и назначение.
7. Сохранить реальные конфигурации, миры, права, экономику, production-подключения БД, AuthMe, AuthEffects и signed V4. Не переносить локальные тестовые env, миры и состояние события.
8. Для `CopiMineArtifacts/items.yml` применять контролируемое слияние каталога по ID с сохранением существующих данных; не заменять весь файл шаблоном.
9. В реальном рабочем `spigot.yml` проверить однозначное конечное числовое значение `settings.attribute.maxHealth.max >= 20000`. Правильный шаблон в Git не доказывает правильность рабочего файла. При необходимости изменить только этот параметр.
10. Проверить сохранение `CUSTOM` в ClearLag `exempt-spawn-reasons`: иначе лимит может отменять необходимые спавны события.
11. Сверить конечные установленные байты и настроить штатный запуск через правильный Paper и Java. Не использовать `/reload` или замену JAR в работающей JVM.

Не копировать локальные loopback/online-mode/RCON-настройки на публичный сервер. Сохранить его действующую модель доступа. Не использовать `--unauthenticated-test-runtime`, отключение signed V4 или поддельные клиентские подтверждения.


## Проверка после установки

- Сверить фактический PID, Java, Paper, порт и рабочий каталог с выбранным инстансом.
- Проверить включение всех ожидаемых плагинов, зависимости и реальную БД; проанализировать ERROR/SEVERE, исключения загрузки, отключения плагинов и ошибки схемы/ресурсов.
- Сопоставить установленный inventory с подготовленным manifest. Если production имеет дополнительные плагины, явно объяснить отличие от проверенного набора из 30.
- Проверить EndEvent status/invariants, затем выполнить один штатный холодный перезапуск и повторить проверку.
- При неуспешном запуске восстановить согласованный набор кода, конфигурации и данных из резервной копии; не оставлять частично обновлённый инстанс.
- Клиент `CopiMineClient-0.1.3+26.3.jar` и ресурс-пак поставляются отдельно и не помещаются в серверный plugins.

При доступной авторизованной игровой сессии проверить волны 6/7, цель и истечение Turncoat, касты и кулдауны, урон/щиты босса, Inferno, гейзеры, Kagune и звуки. Автотесты, запуск сервера и resource-pack acknowledgement не заменяют эту проверку.

Итоговый отчёт должен содержать точный commit, таблицу до/после, конечные хеши, службу/каталог, место резервной копии, результаты двух запусков и оставшиеся ограничения. `nativeVerified` остаётся `false`, пока нет реальных доказательств графики, звука и игрового боя.
