# W1/W3–5: источники моделей и контракт размещения

Источник геометрии W3/W4, компактного заряда W1 и новых структурных текстур —
`resourcepacks/tools/generate_wave3_wave4_structures.py`.
Источник плитки W5 — `resourcepacks/tools/generate_wave5_safe_tile.py`.
Оба генератора записывают только явно перечисленные файлы. Они не записывают
существующие HD-текстуры обелисков, модели W6/W7, Guardian или Kagune.

```powershell
python resourcepacks/tools/generate_wave3_wave4_structures.py
python resourcepacks/tools/generate_wave5_safe_tile.py
python -m pytest -q tests/test_end_rift_wave_structure_assets.py tests/test_end_rift_wave5_safe_tile_assets.py
```

Модели находятся в `resourcepacks/src`, а сборщик копирует всё это дерево
в пакет. Новые модели/текстуры/метаданные зарегистрированы в
`REQUIRED_SOURCE_FILES`; существующие CMD W3/W4 сохранены.
SHA-256 выходов записаны в `manifests/waves_3_4_structure_assets.json` и
`manifests/wave5_safe_floor_asset.json`. Генерация в отдельную временную папку
проверяется побайтовым сравнением с текущими источниками.

## W1

Отдельная PAPER-модель CMD 830029 `end_event_carrier_charge` содержит четыре
компактных объёмных элемента: тёмные грани и светящийся циановый заряд.
Её крупнейший размер — 10/16 блока до масштаба dropped item.
W1 должен использовать её вместо CMD 830009: последний теперь содержит
полноразмерную композицию осколков W3 и не подходит для переносимого заряда.

## W3

Вместо маленькой симметричной ванильной двери создана асимметричная разломанная
рама из 11 каменных частей, 22 лицевых/задних энергетических вставок,
7 объёмных полос мембраны и 8 отдельных пар «осколок + светящийся срез».
Рама имеет открытый проход; мембрана остаётся самостоятельным слоем.
Задняя сторона имеет собственные вставки, все элементы имеют front/back faces.
Верхние части повёрнуты на допустимые для Java item models углы ±22,5°.
Мембрана `end_event_rift_membrane.png` использует 8 различных кадров 32×128
с `frametime=3`, без интерполяции. В кадре 32×72 пикселя образуют высокую
мембрану, остальное — прозрачный padding. Явная обрезка UV сохраняет одинаковое
число texels на мировую ширину/высоту вместо растяжения квадратной картинки.
Старая модель CMD 830007 и исходная
`end_event_portal.png` сохранены для совместимости; каноническая W3 их не
использует. Новый layout-only CMD 830028 `end_event_layout_gate` сохраняет
прежнюю модель входных ворот.

При `ItemDisplayTransform.NONE` Minecraft центрирует item model на (8,8,8).
Поэтому raw floor y=-8 соответствует item-space y=-1, а не y=0.
Рекомендуемая трансформация рамы:

```text
anchor: фактический capture center и игровой пол
translation: (0, 2.24, 0)
scale: (2.24, 2.24, 2.24)
rotation: только общий yaw всех трёх слоёв
```

Размер рамы: 4,48 × 5,6 блока; глубина с энергетическими вставками около
1,42 блока. Осколки расширяют силуэт приблизительно до 4,9 блока.
Раму следует держать на полу и с постоянной шириной при 0/25/50/75%:
прогресс сжимает/стабилизирует мембрану и сдвигает осколки, а не уменьшает
реальную область захвата. При collapse уменьшается вся композиция внутрь
с пересчётом translation относительно середины высоты. Фактическое управление
этими состояниями остаётся обязанностью server presentation policy.

Layout gate использует отдельный CMD 830028 с прежними unit-model bounds;
новые raw bounds W3 не должны менять входные ворота и последующий flow W6/W7.

## W4

Причины невидимой custom-презентации в исходном коде:

- исходный item model имел ширину 14/16 блока, server scale X/Z был около 1;
- реальные непрозрачные клетки занимали до 3×3 блоков и закрывали custom model;
- translation (-0,51, 0, -0,51) дополнительно смещал уже центрированный item;
- raw y=0..16 при NONE и scale y=5 требовал подъёма на 2,5 блока;
- full/damaged/critical использовали одинаковую геометрию и меняли только texture.

Mapping PAPER → CMD 830010/830011/830012 → model JSON в исходном manifest
был согласован. Это не доказывает наличие текущего пакета в запущенном клиенте.

Теперь состояния имеют разную геометрию: 19/16/11 элементов, повреждения
убирают контрфорсы, верхнюю часть корпуса и части короны. Центрированная
модель занимает raw x/y/z=0..16. Плита основания остаётся во всех состояниях;
сохраняется верхний сокет для зарядки/выстрела. Две HD-печати спереди и сзади в full/damaged
состояниях сохраняют квадратный мировой масштаб; исходные HD-файлы не изменены.
Структурные грани имеют UV, рассчитанные на 8 texels/world block.

```text
anchor: center X/Z of journal-owned footprint, floor Y
translation: (0, visibleHeight / 2, 0)
scale: (3.25, visibleHeight, 3.25)
ItemDisplayTransform: NONE
```

Видимые ванильные блоки нужно заменить journal-owned невидимыми collision
cells, сохранив прежнюю физическую геометрию, hit detection и восстановление.
Иначе повреждённый силуэт будет снова заполнен ванильными блоками.
Не применять X/Z breathing к стоящему на полу корпусу.

## W5

Новая бумажная модель CMD 830027: `end_event_safe_floor`.
Исходная 32×32 текстура имеет спокойный зелёно-белый геометрический рисунок,
низкую плиту и четыре тонкие приподнятые грани. Высота модели — 0,021875 блока;
raw y=8..8,35 уже располагается над item-space y=0.

```text
anchor: (cellX + .5, combatFloorY() + 1, cellZ + .5)
translation: (0, .015, 0)
scale: (1, 1, 1)
ItemDisplayTransform: NONE
```

Плитка оформляет существующие safe cells; она не меняет их серверную геометрию.
Durable journal и физические emerald safe cells сохранены. Непрозрачная
плитка покрывает верх каждой клетки полностью с масштабом 1×1; raw emerald
BlockDisplay удалён из видимой презентации. Восстановление остаётся прежним.

## Граница доказательств

Подтверждено автоматическими проверками: размеры геометрии, допустимые
координаты/UV, front/back faces, разные состояния здоровья, анимационные кадры,
CMD mapping, required pack registration, воспроизводимость генерации.

**Не проверено в реальном Minecraft:** итоговые материалы/альфа, свет,
размещение на игровом полу, масштаб в арене, отсутствие clipping/z-fighting,
правильный активный installed pack и фактические состояния capture/HP/fog.

Обязательные кадры: W3 front/back/left/right/diagonal/close/raised плюс
0/50/75/collapse/следующий portal; W4 front/back/side/crown, три состояния HP,
charge/launch/reflect/impact/destruction; W5 warning/inside/outside/edge,
frozen mobs/release. Записать хэши installed JAR/mod/pack и открыть полученные
кадры; наличие файлов и успешная сборка не считаются визуальным подтверждением.
