# Установка CopiMine v6

## 1. Разделить исходники и рабочие данные

Пример размещения на Linux:

- `/opt/copimine/site-v6` — файлы сайта из архива.
- `/var/lib/copimine-site` — SQLite, сеансы, очереди, опубликованные карты.
- `/etc/copimine-site/site.json` — закрытые настройки оператора.
- `/srv/minecraft` — действующий сервер с папками миров.

Python 3.11+ нужен для API и сборщика. Создай виртуальное окружение в каталоге установки и выполни `pip install -r requirements-server.txt`. Для рендера карт нужен Pillow. SQLite, пароли и TOTP используют стандартную библиотеку Python; для зашифрованной очереди уведомлений используется cryptography, для HTTP — Waitress.

Запускай процессы от отдельного системного пользователя с доступом только к нужным каталогам. API самостоятельно запрещает размещать рабочую БД и конфигурацию внутри каталога сайта. Публичные запросы обслуживает ограниченный список файлов; папки server, sources, примеры конфигурации и исходные миры через API не выдаются.

## 2. Создать владельца

Из каталога сайта:

```sh
python server.py --data-dir /var/lib/copimine-site --origin https://copimine.ru bootstrap-owner
```

Команда интерактивно попросит имя аккаунта, почту, пароль от 12 символов и текущий код приложения-аутентификатора. Сохрани показанный секрет 2FA в защищённом месте. Владелец не создаётся по нику, localStorage, параметрам URL или первому входу.

После проверки личности привяжи игровую учётную запись:

```sh
python server.py --data-dir /var/lib/copimine-site --origin https://copimine.ru link-player SITE_ACCOUNT GAME_UUID GAME_NICKNAME
```

GAME_UUID должен быть UUID, который реально использует твой сервер. Совпадение ника с публичным профилем Mojang не подтверждает принадлежность аккаунта. Обычная регистрация на сайте всегда создаёт игрока.

Участник команды сначала включает 2FA в настройках своего аккаунта. Владелец назначает ему роль в карточке игрока. Сервер проверяет роль заново при каждом изменении; равные и более высокие роли защищены от изменения подчинённым.

## 3. HTTPS и веб-процесс

Образец Caddy находится в `deploy/Caddyfile.example`. Он проксирует весь сайт в API, не раздаёт исходники напрямую и перезаписывает заголовок адреса клиента.

```sh
python server.py --data-dir /var/lib/copimine-site --config /etc/copimine-site/site.json --origin https://copimine.ru --trust-loopback-proxy serve --host 127.0.0.1 --port 8787 --waitress
```

Порт 8787 доступен только локально. Внешний доступ идёт через HTTPS. Режим доверия прокси принимает специальный заголовок X-CM-Client-IP только от loopback и проверяет его как единственный IP-адрес. Произвольный X-Forwarded-For не определяет ограничения запросов.

Для самостоятельной проверки API на своём компьютере можно использовать `--origin http://127.0.0.1:8787 --insecure-local`. Этот вариант ограничен локальным адресом; для публикации используется HTTPS.

## 4. Игровые действия

В `integrations/game-bridge/README.md` описаны сборка и установка расширений текущих CopiMine Admin, Artifacts и EconomyCore. Они используют исходники, версии и контрольные суммы из source-lock файлов.

Адаптер запускается рядом с Minecraft и обращается к RCON только через loopback. Через RCON передаётся фиксированная команда с UUID операции; текст, введённый в форму сайта, никогда не становится произвольной консольной командой. Тело операции и квитанция находятся в закрытой очереди и подписаны отдельным ключом.

Укажи adapterUrl, adapterSecret и поддерживаемые adapterCapabilities в закрытой конфигурации сайта. Список для проверенной сборки создаётся из реестра действий и находится в образце `deploy/site.example.json`. Удали capabilities для интеграций, которых нет на твоём сервере.

Запускай обработчик независимо от HTTP:

```sh
python server.py --data-dir /var/lib/copimine-site --config /etc/copimine-site/site.json worker
```

Действие остаётся ожидающим до подписанной квитанции плагина. Повторная доставка использует тот же UUID операции. При перезапуске очередь сохраняется. Если результат неизвестен, система не отмечает операцию выполненной и не выдаёт деньги повторно.

Покупки автоматически выдаются игроку в сети при наличии места. Пользователь вне сети или с заполненным инвентарём остаётся в очереди. Пользовательские предметы создаёт родная фабрика Artifacts с правильными компонентами и привязкой. Баланс сайта и баланс EconomyCore имеют разные действия в админке.

## 5. Карты трёх миров

В архив включены уже отрисованные 304 WebP из предоставленного мира. Для первой публикации в рабочем режиме выполни из каталога сайта:

```sh
python server.py --data-dir /var/lib/copimine-site --config /etc/copimine-site/site.json publish-map .
```

Публикуются только изображения и разрешённые метаданные. Для расчёта задержки используется зафиксированное UTC-время завершения снимка. Дата в имени исходного архива не превращается в UTC предположением.

Для дальнейшего обновления установи mapSource в путь к серверу или папке основного мира. Рендерер читает level-name из server.properties и находит Обычный мир, Незер и Энд; при нестандартном размещении см. MAP_RENDERING.md. Путь к неизменному архиву можно использовать для воспроизводимого снимка, но он не получит новые чанки сам: новые территории берутся из обновляющейся папки миров.

Запусти отдельный процесс:

```sh
python server.py --data-dir /var/lib/copimine-site --config /etc/copimine-site/site.json map-worker
```

В админке / Мир и карта задаются интервал, включение расписания, ручное обновление, публикация, задержка и маркеры игроков. Текст публичной карты формируется из этих же настроек. При выключении публикации закрываются также старые URL изображений. Задачи рендера выполняются отдельно от банов, выдач и платежей.

## 6. Платежи

Провайдер — YooKassa. В закрытой конфигурации укажи paymentShopId, paymentSecret и корректный paymentTest. Ключи также можно передать переменными CM_V6_PAYMENT_SHOP_ID и CM_V6_PAYMENT_SECRET. Статический JavaScript их не получает.

Добавь уведомления провайдера на:

`https://copimine.ru/api/v6/payments/webhook`

Обработчик не доверяет телу уведомления о статусе: он запрашивает платёж через API с серверной авторизацией и сверяет сумму, валюту RUB, получателя, привязку к аккаунту и тестовый режим. Одно подтверждение пополняет баланс один раз. Тестовый платёж сохраняет отдельный статус и не начисляет игровые CM. Текущий курс — 1 ₽ за 1 CM; сумма ограничена сервером.

Запусти сверку независимо от игрового адаптера:

```sh
python server.py --data-dir /var/lib/copimine-site --config /etc/copimine-site/site.json payment-worker
```

Если твоя схема работы требует передачи чеков через YooKassa, paymentReceipt настраивается по твоим реквизитам и налоговым настройкам. В образец не подставлены произвольные налоговые значения.

После настройки сначала проведи собственный тестовый платёж в тестовом кабинете, затем проверь переход на боевые реквизиты. В ходе разработки реальные платежи и возвраты не создавались.

Документация провайдера: [уведомления](https://yookassa.ru/developers/using-api/webhooks), [СБП](https://yookassa.ru/developers/payment-acceptance/integration-scenarios/manual-integration/other/sbp), [идемпотентность](https://yookassa.ru/developers/using-api/interaction-format).

## 7. Почта, SMS и VK ID

Полная настройка находится в **AUTH_PROVIDERS.md**. Запусти мастер `python scripts/configure_auth.py --config /etc/copimine-site/site.json --origin https://copimine.ru`, укажи SMTP/TLS, ключ SMS.RU и ID приложения VK. В кабинете VK ID разреши callback `https://copimine.ru/api/v6/auth/vk/callback`. Для своего домена используй соответствующий origin.

Запусти `notification-worker` с тем же --data-dir, --config и --origin, что и API. Сохраняй файл notification.key вместе с закрытой резервной копией базы. Команда `check-integrations` выводит наличие конфигурации и состояния очереди без секретов.

Коды подтверждают принадлежность почты и телефона; только после подтверждения контакт работает для входа и восстановления. Обязательный 2FA администрации сохраняется при VK, SMS и email. Наличие ключей в конфигурации проверяется отдельно от реальной доставки: перед открытием сайта проверь получение кода на собственный контакт и вход через своё приложение VK.

## 8. Службы и обслуживание

В deploy находятся образцы systemd для API, очереди действий, карт, платежей и уведомлений. Пути и права должны соответствовать твоему размещению. Адаптер Minecraft устанавливается по отдельной инструкции.

Делай согласованные резервные копии SQLite и закрытых конфигураций. Не копируй открытую SQLite только одним файлом при активном WAL; используй штатный backup API SQLite или остановку служб. Команда `verify-audit` проверяет непрерывность локальной цепочки журнала. Для обнаружения полного переписывания базы сохраняй её контрольную точку отдельно от самой базы.

При обновлении сначала останови процессы очередей, замени исходники, проверь тесты и контрольные суммы, затем верни процессы. Не удаляй действующую папку данных, журнал идемпотентности и spool: они нужны для безопасного продолжения незавершённых операций.
