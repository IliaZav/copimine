# Браузерные сценарии проверки v6

Здесь сохранены точные сценарии, использованные для отчётов из `../reports/`. Они рассчитаны на отдельную среду проверки и никогда не должны запускаться с рабочими учётными записями или базой сервера.

Фактическая среда: Node.js, Playwright и Chromium 153 из `@sparticuz/chromium`. В сценариях оставлены пути исходного прогона: проект `/workspace/scratch/3bc02d7967e9/copimine-site`, результат `/tmp/copimine-visual`, модуль Chromium `/tmp/copimine-browser-runtime/node_modules/@sparticuz/chromium/build/index.js`. Для повторения в другом окружении нужно заменить эти три пути и установить соответствующие браузерные зависимости. Запускайте только один Chromium одновременно.

Сервер предварительного просмотра: `python3 serve.py --port 4175 --no-browser`. Серверный прогон использовал `server.py` на 127.0.0.1:8787 с `--insecure-local` и отдельным `--data-dir /tmp/copimine-v6-browser-state`. Файл `browser-fixtures.json` создавался только в этой частной тестовой директории и в проект не включён.

| Сценарий | Назначение |
| --- | --- |
| `auth-v6.cjs` | Настоящий UI с перехватом всех auth API и перехода VK. Не обращается к внешним провайдерам |
| `standalone-v6.cjs` | Прямое открытие file://; можно передать путь к HTML первым аргументом |
| `final-live-v6.cjs` | Отключённые провайдеры, собственные контакты, годовая аналитика; финансовые ответы подставляются только в браузер |
| `capture-v6.cjs` | Основные экраны в desktop/mobile |
| `interactions-v6.cjs` | Предварительный просмотр: инвентари, поиск, санкции, лимиты, корзина, донат, карта |
| `live-v6.cjs` | Отдельная серверная база: вход, права, согласие, баланс и карты |
| `admin-followup-v6.cjs` | CMS, CAS версий, настройки, FAQ, галерея, приватность журнала |
| `preview-admin-final-v6.cjs` | Экраны предварительного просмотра после интеграции новых модулей |
| `preview-cms-followup-v6.cjs` | Повторная проверка нормализации CMS, черновика/публикации и поиска |

Проверки с тестовым временем используют Playwright Clock. Ожидание серверных страниц основано на `DOMContentLoaded` и `CM6.ready`: `networkidle` не подходит страницам с фоновым обновлением сеанса. Сохранённые отчёты фиксируют фактически завершённые прогоны; наличие сценария само по себе не означает, что новый прогон выполнен.
