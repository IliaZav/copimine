## Confirmed defect and implementation

`copimine-world-core/src/me/copimine/worldcore/CopiMineWorldCore.java`:

The first redirect attempt checked whether a source world remained blocked, but a queued retry did not. Opening the End after the first teleport was cancelled could still evict a player on the next tick. Retry also trusted an old destination, did not reject an unloaded/newly blocked destination, and could reuse a location that had become unsafe.

The new `redirectStillValid` path verifies plugin state, online player, operation ownership, source-world current access, actual loaded destination identity and current configured redirect target. Both the prepared first completion and retry use it. Retry computes a fresh safe location; no stale fallback is used. Scheduling marks a retry as owned only after scheduling succeeds, and completion/cancellation always releases the operation lock.

No direct production teleports, world access changes, database writes or live service restarts were performed by this audit.
