# End Rift Wave 7 — spike отчёт по внутренним стенам

Дата: 2026-09-15
Ветка: `codex/end-rift-event`
Окружение: локальный/staging Paper, production не затрагивается

## Решение

Для Wave 7 используется физическая стена из `Material.BARRIER`, собранная из
одноблочных клеток детерминированного raster-профиля. Визуальный слой отделён
от коллизии: поверх нижнего уровня BARRIER создаются временные
`BlockDisplay` с `AMETHYST_BLOCK`. Поэтому клиентский ресурс, отсутствие
клиентского мода или задержка визуального пакета не меняют игровую границу.

Профиль ограничен пятью уровнями высоты, нулевой половиной ширины стены и
лимитом клеток. Для двух комнат граница — одна connected east/west
диаметральная raster-линия; для большего числа комнат профиль строит
детерминированные соседние радиальные границы. Вставка разрешена только в
пассивные клетки арены, не заменяет Core/gate и не записывает поверх жидкости.

## Почему не WorldBorder

`WorldBorder` в Bukkit/Paper — одна мировая квадратная граница с центром,
диаметром и damage/warning настройками. Она применяется ко всему миру и всем
игрокам, а не к отдельной паре комнат или к конкретной клетке арены. API не
даёт независимых радиальных сегментов, проходов между соседними chamber и
журнала исходного `BlockData` для каждой изменённой клетки.

Использование WorldBorder для этой механики дало бы три неправильных эффекта:

1. внешняя квадратная граница изменила бы допустимую область для всего мира;
2. нельзя было бы открыть один completed passage, сохранив соседние стены;
3. нельзя было бы атомарно восстановить только исходные блоки после reset,
   restart или естественного завершения.

Поэтому WorldBorder оставлен только как возможный операторский preview и не
является источником истины для Wave 7 collision/AI/teleport.

## Журнал и восстановление

До первой мутации каждая planned cell записывается в
`HazardMutationJournal` с world UUID, event id и generation. После успешной
установки BARRIER журнал переводится в `APPLIED`. Cleanup повторно читает
журнал даже при пустых runtime maps, восстанавливает `webOriginal`/floor
согласно записи и только затем помечает его `RESTORED`.

Один и тот же путь используется для:

- `/cmend wave clear`;
- natural completion всех chamber;
- reset/отмены текущего objective;
- bootstrap после остановки сервера, где журнал сначала восстанавливается,
  затем текущая generation заново создаёт стену;
- несовместимого generation, для которого старые сущности и клетки не имеют
  права продолжать combat.

Для disposable Wave 7 добавлен отдельный generation-bound recovery marker.
Он позволяет локальному live harness проверить stop/start, но при обычном
`clear` удаляется вместе со всеми transient entities и не переводит durable
официальный event в следующую фазу.

## Проверки и ограничения доказательства

Статические и pure-policy проверки проверяют `WALL_HALF_WIDTH = 0`, высоту 5,
лимит клеток, connected/raster расчёт, BARRIER mutation, AMETHYST visual
layer и journal replay. Live harness должен писать отдельные маркеры:
`LIVE_WAVE7_ONE_BLOCK_WALL_PASS`,
`LIVE_WAVE7_COMMAND_CLEANUP_PASS`,
`LIVE_WAVE7_NATURAL_COMPLETION_CLEANUP_PASS` и
`LIVE_WAVE7_RESTART_RECOVERY_PASS`.

До получения свежей полной матрицы кадров и поведения непосредственно в
нативном клиенте Minecraft это не следует выдавать за визуальную release
проверку.
